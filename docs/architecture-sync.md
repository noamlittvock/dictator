# Mac connections and sync

[Architecture overview](architecture.md) · [Development](development.md)

## Macs and roles

Every Mac runs the same app. Each install has a role (`CoreRole`), shown in Settings in plain words:

| Role in code | In Settings | What it does |
|---|---|---|
| `standalone` | On its own | One Mac, nothing shared. |
| `core` | Main Mac | Keeps the main copy of history, the dictionary and shared settings; other Macs connect to it; runs every dictation's session logic. |
| `edge` | Connected to a main Mac | Records, types and keeps its own copy of history; the main Mac decides what happens. |

The main Mac (the Core) listens on its Tailscale address, port 7880 (`EdgeProtocol.corePort`), and only accepts peers in Tailscale's range (100.64.0.0/10). Each connected Mac (an Edge) opens one WebSocket to it and says `hello` with a pairing token. The protocol is JSON text frames plus binary frames for audio (`Models/EdgeProtocol.swift`, `EdgeProtocol.version` 2). Tailscale encrypts and authenticates the link; there is no TLS on top.

The Core also runs a local Edge for itself, so a single Mac and a group of Macs use the same code path (`CoreHost`, `SessionBroker`). A connected Mac that loses its Core falls back to working on its own until the Core is back.

## The setup picture (Settings › Your Macs)

Each Edge reports what it has in its capabilities: product name, memory and Tailscale IP (`MachineProfile`), microphone, Ollama models, speech models, and whether Apple speech is available. The Core's `SetupDirectory` keeps every Mac that has ever connected (offline ones stay until removed), matches speech server addresses to Macs by Tailscale IP, checks each server's `/health` every 20 seconds, and sends the result (`SetupSnapshot`) to every Edge in a `setup` message. Each Mac keeps the last one on disk, so it can still draw the page when the Core is off.

That persisted report is inventory, not current connectivity evidence. While a Mac configured to connect to a main Mac is disconnected, Your Macs and General explicitly use the current connection state: other Macs are unavailable through the relay, cached speech-server health is shown as unverified, and sync routes wait. A direct speech server may still work; the UI does not claim it is down. Current local speech and Ollama inventory can still make this Mac's own models available. The presentation preserves the original report, its inventory and timestamps; it changes no routing, stored fields or wire messages. Without explicit connection context, these views fail closed for a connected-Mac role.

## Adding a Mac

While Settings › Your Macs › Add a Mac is open on the main Mac, it accepts join requests for ten minutes and announces itself on the local network (`_dictator-setup._tcp`). The joining Mac lists what it finds, or resolves a typed Tailscale name (only addresses in Tailscale's range are accepted), and sends `pair.request`. The Core answers with a random six-digit code (`pair.code`), shown on both Macs; only the user's OK on the main Mac sends the pairing token (`pair.approved`). The joining Mac saves it and connects with `hello`. One join waits at a time; a copied invitation (`dictator-invite:` plus base64 JSON of name, address and token) is the fallback. An invitation must carry a Tailscale address, and `coreURL(for:)` accepts only such an address or a well-formed `*.ts.net` name. If the pairing token can't be saved, the join fails and the role doesn't change.

Removing a Mac requires confirmation on the main Mac, whether the other Mac is connected or offline. `CoreHost.revokeAccess` first asks `CoreServer` to generate and atomically replace `core-pairing.token` through `LocalSecret` (a 0600 temporary file, flushed before rename). On the server's serial receive queue it swaps the in-memory token, disconnects the removed Mac, then sends `pair.token.rotated` only to the remaining authenticated connections. Hello validation uses that same queue: an old-token hello processed after the swap receives the existing `error` with code `auth`, even if its socket was already open. A failed write leaves the old file and in-memory value in place and disconnects/removes nobody; Settings explains the failure. With no listener, the replacement is still saved for the next listener. The broker disconnect happens before `SetupDirectory.forget`, whose offline guard remains in force. Queued callbacks from a disconnected connection cannot restore its listing or deliver more requests.

Each updated connected Mac saves the replacement for the exact main-Mac address through `PairingCredentialStore`, updates its reconnect credential, then sends `pair.token.saved` with a rotation ID only. The server accepts an acknowledgement only for that connection's pending rotation. Secrets never enter logs, settings mirroring or history. These are optional message types; `EdgeProtocol.version` stays 2. Older peers ignore the rotation and remain connected until their link drops, then need to join again. A Mac that disconnects during delivery may also need to join again; there is no rollback to a revoked token.

An offline Mac cannot receive the replacement. Its next hello is refused, including if it changes its claimed Mac identity. `CoreConnection` turns `auth` into a plain explanation pointing to Settings › Your Macs › Add a Mac on the main Mac. It stops reconnecting, and the coordinator's liveness watchdog does not rebuild that stopped connection. Saving a replacement unsuccessfully also stops the connection with an explanation and sends no acknowledgement. Your Macs offers the existing Join Another Mac’s Setup sheet in this state; joining again creates a new connection using the saved new credential. No local history is deleted. The removal confirmation names the other offline Macs that must join again. Any configured speech server has a separate key that a removed Mac may still hold, including a server on the main Mac or loopback. Removing a Mac does not change that key; see [server/README.md](../server/README.md) for changing it.

## History, dictionary and settings

- Saving history is on by default for a new install.
- Home retains its history feed while switching tabs. It loads the newest 100 entries first and reads another page only with **Load older entries**. Only loaded pages are laid out, using an eager stack to avoid the lazy stack's accessibility-scroll trap after a page append. Local reads run on background SwiftData contexts. Filters query the whole local store using metadata, so older destinations and typed entries remain accessible without loading every transcript. A history revision refreshes the feed; export and Clean Up read the whole store only when requested. Replication keeps its existing byte-budgeted pages and exclusive `(timestamp, id)` cursors.
- Every Mac reads and writes only its own SwiftData store (`~/Library/Application Support/Dictator/Dictator.store`). `HistorySyncEngine` replicates with the Core: new rows start as pending and are uploaded by id, missing live rows are pulled down, and deletes and dictionary edits use the persisted outbox (`SyncOutboxItem`).
- Explicit history deletes save content-free `HistoryDeletion` records (ID and deletion time) in the same local transaction as row removal and, on a connected Mac, the outbox item. These records stay indefinitely for offline peers. On attach or a full sync, each connected Mac sends local deletion IDs missing from the main Mac's proof in bounded, idempotent delete requests, then refreshes the manifest. This includes deletes made while on its own and repairs proof lost by an older main-store restore; the outbox is not the only source of intent. Delayed uploads, old pulls and repeated imports cannot recreate deleted IDs. Import previews count previously deleted IDs separately and keep them excluded.
- The main Mac serves deletion proof through the existing byte-budgeted manifest's optional `deletedAt` field; a marker's `timestamp` is its deletion time. Deletion pages use a unique indexed key encoding the exact date bits and UUID, so a large one-call deletion does not rescan its whole timestamp group per page. Updated peers retain the proof and remove matching rows, including pending ones, before uploads. History notifications and local pushes walk the complete metadata manifest: future-dated or imported rows must not hide a later deletion marker. Only unknown live rows and rows whose optional `hasEditedText` marker is newly present need their text fetched. The first observed edited stage is immutable; replication merges that stage into an existing row without changing text, timestamp or aggregate stats. This adds a metadata scan per history pass.
- Missing rows without deletion proof still use the original wipe guard: the engine refuses to remove more than 50 synced rows when they also exceed 25% of the remaining synced set. Explicit markers authorize only their own IDs. Old peers ignore the optional field and cannot apply these deletions, so every Mac must be updated before relying on cross-Mac deletion. Deletes made before this metadata existed have no proof and retain the legacy guard. The protocol version stays unchanged.
- Shared settings are mirrored between the Core and every Edge (`CoreSettingsMirror`, `CoreSettingsDTO`): whether history is saved, clean-up on or off, the typed-history policy (`surfacePolicyJSON`), which Mac records (`micOwnerEdgeID`, empty for Automatic), which Mac does the other jobs (`setupRoutingJSON`), the commands and lists (`voiceLaunchJSON`), vocabulary pack selection (`vocabularyPacksAutomatic`, `vocabularyPacksOn`, `vocabularyPacksOff`), correction learning (`learnFromCorrections`, on by default). The recording picker is available in every role, including on connected Macs whose main Mac is distant or screenless. Its optional wire field preserves the local choice when absent and explicitly returns to Automatic when empty; validated changes update the main Mac’s broker without changing its role or connection. Changing one on any Mac changes it everywhere. The hotkey mode is set by the Core and pushed in `config`.
- Sync events are logged as `sync:` lines in `~/Library/Logs/Dictator/hotkey.log`.

**Dictionary matching.** Recognition hints reach the speech server, WhisperKit and Apple, including Commands and Teach. They are ordered by owner name, starred words, then frequency with recency breaking ties, Commands names, nearby words and packs; in Commands mode its names come first. Nearby text is currently empty; Dictator does not read around the cursor for hints. `vocabularyHintInput` fills fields from mirrored selection, cached installed apps and configured languages, using the target Mac’s app identity from the session snapshot. Pointer-only focus reports preserve the last app report for that same Mac. Sentence frames and the 200-token Whisper budget live in `shared/vocabulary-hints.json`; each Whisper engine fits whole terms with its own tokenizer, including the frame after language choice. Apple receives the first 100 ordered terms. The server splits hinted long audio at quiet points into windows under 30 seconds, supplying the same prompt to each; hintless decoding is unchanged. WhisperKit's VAD chunking copies prompt options to every chunk, with prefill enabled for hinted automatic-language decoding too. Take diagnostics retain the fitted term count, never the hint words. Clients requesting JSON receive `text` and `raw` (before dictionary/clean-up); older clients retain plain text.

Vocabulary entries preserve recognized spelling except single ordinary Title case words such as Slack, Notion and Whisper, which are recognition hints only. Mixed-case, all-caps and multi-word vocabulary entries, and explicit replacements, still rewrite text when clean-up is off. Matching ignores case and accepts spaces, hyphens or comma-space between pattern words; runs of single letters also accept dots, hyphens or no separator. Patterns with at least three letters retain a trailing s, es, 's or ’s. Hebrew patterns accept one attached prefix letter from `VoiceLaunchText.hebrewPrefixes`, preserving it. Letters, numbers, combining marks and underscores otherwise prevent matches inside larger words. Longer phrases win at the same position; explicit replacements beat vocabulary at the same span. Matches are chosen from the original transcript, so one rule's output is never input to another. AI clean-up receives corrected text and restores target spellings afterwards without replaying source rules. Both matchers read `shared/dictionary-matching-fixtures.json` in tests. A consistently misheard name still needs an explicit replacement.

**Vocabulary packs.** `shared/vocabulary-packs/<id>.json` supplies English terms, summaries, bundle IDs and an optional always-on flag; `project.yml` bundles the folder and `VocabularyPackCatalog` loads its top-level files. Common terms are always included unless explicitly off. Automatic selection adds packs associated with locally installed apps or the reported destination app (which can be on another Mac); manual On adds packs and Off beats every source. Only the person's configured languages apply (regional codes share their base language). Active packs are ordered by destination app, manually enabled fields, installed-app fields, then always-on packs. Terms are merged round robin in each pack’s authored order, with destination packs taking two turns per round, so fields share the 200-token budget. Terms are de-duplicated without changing the first spelling; personal words remain ahead of packs. `InstalledApps.bundleIDs()` performs cached, background LaunchServices queries for catalog bundle IDs, without scanning folders or launching apps. Installed-app results remain local; only the three optional pack policy fields travel through the settings mirror. Medicine, law, finance and marketing/sales currently use manual selection because they lack reliable, specific native-app associations.

Each pack's `metadata/<id>.json` owns the display text, language, app list and always-on flag. Original authored candidates live in `candidates/<id>.txt` (120–160 terms). Shipped starter packs contain the first 45 candidates and are not measured. `scripts/vocabulary-packs/evaluate.py --model-repo <local-directory-or-cached-repo-id>` explicitly evaluates four installed English macOS `say` voices with matched unaided/hinted offline MLX Whisper decodes. It uses `shared/vocabulary-hints.json`'s English frame when present, otherwise the contract's sentence frame. It ranks unaided misses first, then recovered terms, fits the complete prompt to 200 tokens using that model's tokenizer (including Whisper's leading space), and replaces the pack JSON using the same metadata. Audio is temporary outside the checkout; optional score reports must also stay outside it. It never downloads models or voices or contacts the speech server. `--dry-run` tests three terms per pack with stub audio, decoding and token counts, writes only outside the checkout, and does not measure recognition. Unit tests use synthetic text and fixtures only.

**Dictionary screen.** Fields are equal-height toggle chips that wrap to the available width in both Dictionary and welcome; a dot, tooltip and one legend identify automatic app selections. Always-on fields stay out of that row. One words list combines spelling and heard-as rules; heard-as spellings are shown once ignoring case, and forgotten rows never appear. Dictionary pages sort lexically by `(pattern, id)`. New peers send optional `afterID` with `afterPattern`, preserving every equal-pattern identity across count and byte-budget boundaries; omitting the id retains the older exclusive pattern-only cursor. Search includes heard-as spellings. The same Add/Edit sheet starts with Word and reveals optional heard-as fields; Return saves. More starts collapsed and remembers its state per window through `SceneStorage`; it holds phrase matching, ordered recognition words and space used, learning and automatic-field settings, and text import/export. Phrase matching calls `CleanupPrompt.applyReplacements` with the same filtering as dictation (forgotten rows and learned hint-only rows excluded). Recognition preview builds from the page’s loaded entries using the same explicit-input `VocabularyHint.vocabularyHintInput(entries:...)` builder and `orderedTerms` as dictation, so stars and reloads apply without reading a second repository. Words that do not fit appear as a count with a collapsed disclosure for the list. Preview uses an already loaded local tokenizer when available, otherwise a labeled conservative estimate; it never loads assets or calls a speech service. Preview is for ordinary dictation without a destination app; the actual engine, language and destination can change what fits. Import can replace conflicting heard-as spellings in place. Export uses the existing plain word / `heard -> spelling` format, with a version comment and JSON-escaped `@word` lines for otherwise ambiguous words; the parser only recognizes escapes under that version header and continues reading old imports. Export preserves spellings and rules, not star/usage metadata. The welcome flow adds an optional fields step with equal Skip and Use actions. It loads both explicit On and Off choices; Use saves both, while Skip changes neither. Voice history rows offer Fix a word with contiguous word chips and plain confirmation; typed rows do not. The sheet displays the latest edited stage when present and sends optional `selection` containing its full text snapshot and offsets counted in Swift Characters (extended grapheme clusters). The main Mac checks the snapshot and selected text against the current row, refuses stale selections before any learning, and replaces only that occurrence. Legacy requests without a selection can teach the dictionary but cannot change the history sentence.

**Learning from corrections.** `Services/Dictionary/CorrectionLearner.swift` is a pure Unicode diff and validation policy with an injected spell checker. It accepts at most three changed spans of one-to-one word substitutions, and declines unrelated rewrites, insertions/deletions, short/long terms, markup, code, paths, addresses, numbers and opaque identifiers. The production adapter checks ordinary words through `NSSpellChecker` in the person's configured languages (system preferred spelling languages when none are configured). Internal brand capitalization can pass that ordinary-word filter. A new accepted spelling is a hint-only vocabulary row (`origin: "learned"`); it is excluded from the replacement/clean-up dictionary. Recognition hints read dictionary rows independently, so that spelling can aid all engines without creating an automatic rewrite. A matching heard-as rule needs two distinct observed corrections; the explicit History action `DictatorViewModel.learnCorrection(heard:corrected:entryID:selection:)` uses the same filters and can add that rule immediately. The main Mac owns learning. The persistent confirmation ledger in defaults contains salted hashes, bounded counts and dates, never words; it retains at most 64 pending pairs for 30 days and 128 recent observation hashes. Additions are limited to five dictionary rows per day. Diagnostics log only candidate/addition counts.

On the Mac that inserted the dictation, `EditWatcher` performs one post-insertion AX read and one final read when focus leaves the field, the app changes, another dictation begins, or 60 seconds elapse. There are no text-change/keystroke observers or reads while typing between those events. It retains only the inserted span, short neighbour anchors and an opaque field handle in memory, then discards them. The final AX string-range read is bounded to the insertion window and its anchors, adjusted by the field's length change. Length only bounds the read: it never proves ownership. The insertion must be uniquely located, its anchors must still bracket a single span, and every changed word must be a plausible one-to-one substitution. An equally good alignment that adds characters at either outer boundary also fails closed. Extensions at either end, extra or missing words (including when the right anchor is empty), changed neighbours and ambiguous anchors abandon the entire observation: nothing is saved, sent or learned.

Correction learning has its own switch (`learnFromCorrections`, on by default), independent of history saving. Secure input/fields, unreadable terminal fields, Pause, and places explicitly excluded for either voice or typed capture are skipped before any field read; the gate is checked again before the final read and delivery. Default-off typed history is not an explicit exclusion. When typed capture is allowed for that place through `AppSettings.captureDecision`, an owned corrected sentence may become the existing dictation row's first `editedText`. Otherwise the inserting Mac filters it into individual word pairs using the ordinary-word/unsafe-text checks before delivery; no corrected sentence is sent or kept. Pairs are never logged, and the confirmation ledger holds only hashes. Turning history off prevents every history-stage write but still permits filtered pairs to teach the dictionary. Deleting a history row cannot recreate it; learning does not require a history row.

Insertion does not await learning. A connected Mac sends ephemeral observations in the optional `RepoRequest.correction` request, with optional `pairsOnly` and destination `context` fields; older main Macs ignore unknown fields/requests. There is no outbox, offline typed capture or queued transcript. The main Mac rechecks correction consent and typed-history policy; the history repository independently enforces typed consent and first-edit-only semantics on automatic `saveEditedText`. Deliberate History fixes use separate `saveManualEdit`, which checks the global history switch and expected current text, allows later fixes, and never recreates a missing row. Each manual fix advances a default-zero `editedTextRevision`, optional in DTOs and manifests; sync fetches newer revisions even when both Macs already hold an edited stage, and an older upload cannot overwrite one. The original final dictation stays in `text`; fixes replace `editedText`. Correction responses retain `kind: "ok"` with optional `correctionOutcome` (history saved, spelling learned, and optional learning failure). Main-Mac save errors return repository errors, and the requesting Mac shows the actual outcome. A successful history fix followed by failed dictionary learning is reported as partial success. Older main Macs returning bare `ok` are described as receipt without a confirmed save. History stages share text's replication limits and byte-budget truncation. `DurableTranscriber` aggregates raw and final chunks in order for takes over 110 seconds, using each chunk's returned text when its raw stage is absent, then publishes the complete raw stage once for history. Recovery uses the same stage-aware chunker, and Shortcuts Dictate saves the listened words before clean-up. `heardText` uses the transcription result's optional `rawText`, falling back to its returned text on older engines/servers.

Dictionary rows also carry optional/defaulted star, usage, origin and forgotten fields. Deleting a learned row retains an `isForgotten` tombstone, hidden from the screen, hints, replacements, usage and future learning. New peers request dictionary pages with optional `includeForgotten: true`. Requests without that field (or with false) receive active rows only, filtered before pagination, so older peers discard previously mirrored forgotten rows instead of using them. New peers retain local tombstones even if an older main Mac omits them. Undo clears `isForgotten` on the same learned identity, preserving metadata; manually adding a matching forgotten pattern of the same row type also reuses that identity and sends its cleared tombstone through the normal outbox. An omitted forgotten field from an old peer cannot clear a tombstone. Restored words participate in learning normally even when a different heard-as rule for that spelling remains forgotten; the forgotten rule still blocks recreating its own source pattern. Manual/imported rows keep their existing delete/undo behavior. Patterns remain nonunique across independently created vocabulary and rule rows, hence the composite dictionary cursor. Only the main/standalone Mac counts complete dictionary terms in finished dictations' final text. `DictionaryUsageBatcher` coalesces counters in memory for 60 seconds and commits once, plus a synchronous quit flush. Usage writes are quiet: no `onChange`, revision notification, broadcast or outbox entry. Connected Macs pick up the counts on the next real dictionary change. Repository notifications distinguish local edits from mirror-applied changes: both refresh the UI, but a mirror-applied change never schedules a history push pass. All new nonoptional SwiftData properties have declaration defaults, and the stages are optional, for unversioned lightweight migration. Optional DTO fields use Codable's synthesized `decodeIfPresent`; an omitted old-peer field never resets newer metadata.
