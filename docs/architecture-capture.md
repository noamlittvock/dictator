# Commands, capture and Datasets

[Architecture overview](architecture.md) · [Development](development.md)

## Commands

A spoken **pattern** fills named **slots**, and the slots feed a linear chain of **steps**. Everything is deterministic: exact matching against fixed words and user lists, no model judgment.

- **Data** (`VoiceLaunch.swift`). `VoiceLaunchConfig` (`version: 2`, `lists`, and `commands`, stored as `shortcuts`) is one shared setting (`voiceLaunchJSON`, mirrored like the others through `CoreSettingsDTO`/`CoreSettingsPatch`, validated in `RepoServer` and `LocalCoreSettingsRepository` by `VoiceLaunchConfig.validate`). Caps: 100 commands, 20 lists, 500 entries per list, 20 steps per command. A list (`VoiceList`) has fields and entries; an entry has the names you say (first is the display name, the rest aliases) and a value per field. A command has a readable pattern (`Email {person:People} [subject {subject} body] {body}`: fixed words, `{name:List}` list slots, `{name}` text slots, one level of `[optional]` groups), an optional `cleanUpSlot`, and steps. Step types: `openLink`, `openApp`, `waitForTextField`, `typeText`, `pressKey`, `runInTerminal`, `confirm`, `runAppleShortcut`, `webhook`, `appendToFile`, `runWorkspace`. Validation gives plain-words reasons: the pattern starts with a fixed word, a text slot is last or followed by a fixed word (its end marker), slot names are unique, lists exist, references (`{slot}`, `{slot.field}`) exist, link schemes are in `allowed_link_schemes`, and acting steps (Return or ⌘Return, Apple Shortcut, web request) need an earlier `confirm`.
- **Gesture.** `HotkeyService` watches two `KeyCombo`s on the same tap, held in `HotkeyTriggers`: the dictation keys and the Commands keys. Each is per-Mac, stored in `dictationKeys` and `commandKeys`, and defaults to Right ⌥ and Right ⌥ + Right Shift; `hotkeyKeyCode` keeps the first dictation key. Any regular key in a combo is held back from the app in front. `KeyComboRules` refuses keys that could not work. The Commands keys being down at any point while the press lasts, or when a tap starts, sends `shortcut.mode` (`EdgeMessage.voiceCommandMode`, a new message type, no version bump); the broker marks the session and re-broadcasts it (`SessionStateUpdate.voiceCommandMode`, optional), so the Mac showing the indicator, which may not be the one with the keyboard, changes the badge and adds a "Commands" label. Plain Right ⌥ never does.
- **Matching happens on the Core**, on the raw transcript before clean-up (`CoreHost` calls `DictatorViewModel.resolveVoiceCommand` for Commands sessions only). `VoiceLaunchEngine.match` tokenizes Unicode-aware (Hebrew works), compares on lowercased, punctuation-stripped words, and keeps each slot's original text. A small backtracking matcher takes exact fixed words, the longest list name or alias, marker-ended text slots up to the first marker (at least one word), a final text slot that takes the rest (may be empty), and optional groups tried present then absent. The whole transcript must be consumed. The winner has the most words consumed by fixed words and list slots; a tie between different commands means no match. `VoiceLaunchEngine.plan(for:in:)` is the pure function (match, slot values, rendered steps, or why nothing matched); the Core and the tests use it. In Commands mode the speech step skips clean-up, and its fixed words and list names lead the recognition hints on every speech route.
- **Clean-up.** Only the command's `cleanUpSlot` goes through clean-up (when it is on); dictionary replacements apply to every text slot; list values never go through clean-up. If nothing matches in Commands mode, all the words are kept on the clipboard with a notice; nothing is typed. Plain dictation still uses the normal insertion path.
- **Rendering.** `VoiceLaunchEngine.render` encodes each value for where it is used: percent-encoded query components in links (trailing punctuation dropped from text slots that weren't cleaned up), raw in typed text, one shell-quoted word each in the Terminal script (`ShellQuote`), JSON for webhooks. Unknown or missing optional slots render empty.
- **Delivery happens on the target Mac.** The Core sends the resolved `VoiceLaunchPlan` as `insert.launch` (`CoreMessage.launchInsert`, a new optional message, no version bump; older Macs ignore it) instead of `insert`; the target answers with the usual `insert.result`. No-match notices and older Cores still use the first version's `insert.shortcut`. `VoiceLaunchExecutor` runs the steps in order and stops at the first failure with an alert naming the step ("Couldn't find a place to type in WhatsApp"); later steps never run. It refuses a plan that has a step this build can't run before running any. The steps: `openLink` (scheme checked again on the target), `openApp`, `waitForTextField` (expected app frontmost and an editable focused element, default 8 s), `typeText` (`PasteService`), `runInTerminal` (private self-deleting `.command` script). The executor also supports `confirm`, `pressKey`, `runAppleShortcut`, `webhook` and `appendToFile`, described below. If a step fails the main words stay on the clipboard. The target returns the encoded alert as a failed insertion outcome; the existing initiator-only idle handler shows it on the dictating Mac and retains the recovery recording. No-match notices without an interactive near-miss picker follow the same route, preserving tie details and the Commands action.
- **Apps and workspaces by name.** The “Open an app” card (`open-app`, `Open {app}`, example “Open Safari”) has one `openApp` step whose `text` is `{app}`; existing `bundleId` steps take precedence and keep their behavior. The “Workspaces” card (`open-workspace`, `Workspace {workspace}`, example “Workspace writing”) has one `runWorkspace` step whose `text` is `{workspace}`. Neither has clean-up or a confirm pause. Both name fields render on the main Mac through `VoiceStepRenderer`, including deferred answers, but resolve on the target Mac. `VoiceNameResolver` folds case and diacritics, removes spaces and punctuation, a `.app` suffix and a trailing parenthesized label. It requires one exact normalized match, never a prefix, fuzzy match or model guess. Empty names and multiple matches fail; ambiguous alerts list the matching names. App enumeration (`VoiceInstalledApps`) runs off the main thread, reading /Applications, /System/Applications, /System/Applications/Utilities and ~/Applications, their immediate child folders, and no app bundle contents. Distinct installations with equal names remain ambiguous; duplicate paths are removed. A cached background snapshot adds this Mac’s app names after command/list hint words within the existing 400-item limit; recognition uses the previous snapshot and refreshes it without blocking key-down.
- **A routine's own voice command.** `VoiceStep.workspaceId` is optional, included in coding keys and preserved through normal/deferred rendering and `insert.launch`. On the target Mac it takes precedence over name lookup, including after a rename; a missing ID fails with the spoken phrase and no suggested replacement. Without an ID, the Workspace card and existing text/slot name lookup are unchanged. ID-based rendering carries the raw spoken phrase in `text` for a failure; linked commands without text slots retain those words as `mainText` for the clipboard. `VoiceWorkspaceLink` in `VoiceLaunchEditing.swift` provides pure find/add/phrase-change/remove/rename operations. Creation makes an enabled command named after the routine, with literal words, one ID-linked workspace action, no clean-up and no confirmation pause. `VoiceBuildProblems.workspacePhrase` rejects typed curly/square brackets, uses the existing parser and matcher (including off commands, aliases and filled-in sentences) to name conflicts, and applies the normal save limits. All writes use `AppSettings.updateVoiceLaunch` and the existing settings mirror. Workspaces offers the command row on every routine, independent of its actions and this Mac's execution permissions: add/edit in a one-field sheet with this Mac's actual keys, remove without confirmation, enable an off command, and show the first link plus a count of others. Phrase edits retain the command's other settings/actions and enabled state. Teach remains available in the Commands editor. The Run a workspace editor offers saved routines by ID or “The name I say”; summaries resolve the current name from saved routines.
- **Workspace execution and compatibility.** `VoiceLaunchServices` injects names, app opening and awaitable workspace execution for synthetic tests. `WorkspaceLaunchController.runAwaiting` shares `performRun`, waits for local changes and normal multi-Mac fan-out, and throws for a busy controller or failed run. Workspace run replies and fleet reports carry an optional `failure` alongside the existing summary, so remote failures and missing replies reach the voice failure path; older peers omit it and retain their summary behavior. Later steps run only after it finishes successfully, in their original order. The insertion watchdog adds a 60-second budget per workspace step, covering capture, cooperative changes and the fleet round trip. Failures use the existing executor `Failure`/`insert.result` path, keep the words on the clipboard and show a plain alert on the dictating Mac. **Kind decoding remains strict:** an older build that reads a voice config containing `runWorkspace` cannot decode that config and reads Commands as empty. Update all Macs before enabling this step. Validation is not weakened and `EdgeProtocol.version` is unchanged.
- **Duplicates and ties.** Catalog/card adds reuse and enable a command with the same parsed `matchingKey` (including patterns with different slot names), rather than adding another. The editor reports equal patterns through `VoiceBuildProblems`. Runtime ties name the matching commands, ask the user to turn one off or change what they say, retain the words on the clipboard, and offer an action opening Commands.
- **Timing.** Each step logs `voicelaunch: step 2/3 openLink ok 12ms` to `~/Library/Logs/Dictator/hotkey.log`, plus `voicelaunch: total 431ms (from key release) 3 steps`.
- **Ready-made.** `shared/shortcut-catalog.json` (version 5; `groups` lists the headings of the simple view in order; each template may carry a `card` with a plain title, an example sentence, the one question it asks, its `group`, a one-line `does` (a variant's `does` is shown while that variant is in use), and icon hints: `apps` (bundle identifiers) and `site` (a host)) holds `allowed_link_schemes`, the empty lists People (phone, email) and Projects (folder), and templates made of the same parts. It includes "WhatsApp and send" (`WhatsApp and send {person:People} {message}`: open the link, wait for WhatsApp's text box (`net.whatsapp.WhatsApp`), ask, press Return). A template can set `"hidden": true` to stay out of the tab. The Commands tab has two layers. The simple layer (`VoiceLaunchView`) shows cards (from `VoiceCommandCatalog.runnable`; `VoiceCardsSection`, logic in `VoiceCards`: a switch enables or disables the catalog command; WhatsApp asks check-first or send-right-away and keeps exactly one of the two templates, the send one taking the plain pattern; Claude Code asks for project folders and creates Projects entries), a card's icon (`VoiceIconSource`: the hinted apps, the hinted site, then what its first action reaches — the app it opens, Terminal, Shortcuts, the app for a link scheme, or the link's host — falling back to a symbol for the action or the title's first letter; drawn by `VoiceIconView`; website icons come from `SiteIconStore`, which asks the site for `apple-touch-icon.png` then `favicon.ico`, sends only the host, caches in Caches/SiteIcons and never fetches under tests), tabs (`VoiceLaunchTab`: Things to say, People, and Apple Shortcuts once that card is added), an "On now" strip, compact cards that open one at a time, a "How to say it" legend that folds once anything is on (`VoiceHowToSay`), People (`VoicePeopleSection`, `VoicePeople`, the system `CNContactPicker`, and Check name, `VoiceCheckName` over the same `VoiceTeachSession` with two takes and auto-saved non-conflicting spellings), and "Build your own…" at the top. Every word shown is drawn by role through one view, `SpokenPhraseView` (`PhraseChip`: a solid key for the start word, an outlined pill with a symbol for a person, project or Shortcut, italics for your words; captions optional and off on the cards), fed by `SpokenPhrase` (start word / who, project, shortcut or which / your words, from a pattern plus an example sentence, a plan, or a near miss); it is used on cards, the near-miss notice, Check name, Try it and the progress notice. The advanced layer (`VoiceAdvancedView`) holds your commands (`VoiceCommandEditor`: plain-words validation, a step list with add/move/remove/configure), your lists (`VoiceListEditor`, with full Teach), and a "Try it" box (`VoiceTryItResult`, which calls `plan(for:in:)` and runs nothing). The step menu is `VoiceStep.Kind.addable()`, driven by `VoiceLaunchExecutor.supportedKinds` (now every step type). Adding a step that acts for real (`VoiceStep.isActing`) with no "Ask before continuing" earlier inserts one with a default summary (`[VoiceStep].addStep`, `VoiceStep.defaultConfirmSummary`). The logic lives in `VoiceLaunchEditing.swift` so it is testable. On the target Mac `VoiceLaunchExecutor.run` reports each step to a `VoiceLaunchProgress` (started, done, failed, cancelled, and a per-second countdown), shown by `VoiceLaunchProgressController` in the dictation alert's style.
- **Apple Shortcuts bridge** (`VoiceShortcutBridge.swift`, `VoiceLaunchActing.swift`, `VoiceAppleShortcutFields.swift`). `runAppleShortcut` runs `/usr/bin/shortcuts run <identifier or name> --input-path <file> --output-path <file> --output-type public.plain-text` as an argument array (never a shell), with a per-action time limit (10, 30, 60 or 120 s, default 30; `timeoutSeconds`). The input and answer files live in a private 0700 folder (files 0600) that is removed after the run. *Values in:* a new action sends everything said as `input.json` (`{shortcut, said, values, mac}`; a list value is an object of its name and details; the cleaned slot is the cleaned text; `said` is the raw transcript; Unicode is kept). `inputMode` absent means the older plain-text `input.txt` from the `text` field, so existing actions keep working (nothing is migrated in the stored data). *Values out:* the answer file (up to 64 KB, longer is cut and noted in the log; empty is fine) becomes a value named by the action (`VoiceStep.answerKey`, shown as "answer from Remind"); if it parses as a JSON object its keys are details (the action's `answerDetails` list them for the bubbles). *Deferred rendering:* `VoiceStepRenderer` holds the one set of encoders (percent-encoded in links, raw in text, raw folder and argument for the terminal, JSON for the input file). The Core renders every step with it except a step that uses an answer or builds the JSON input (`needsDeferral`); that step travels with `VoiceStep.deferred` (its templates, the known values, the clean-up slot and the raw words) and its own text fields left empty, so an older Mac (no new message, no version bump) finds nothing to run instead of half a template. The target Mac renders it just before the step runs, with the answers so far and its own name. Validation (`VoiceLaunchConfig.validate` and `VoiceBuildProblems`) allows an answer only in an action after the one that gives it. "Type the answer" is a `typeText` whose text is the answer; the Shortcut's "Type its answer where my cursor is" toggle adds or removes it right after the Shortcut. *Picker:* `shortcuts list --show-identifiers` (run on the Mac showing the editor; `VoiceShortcutList` parses `Name (ID)`), Refresh, Open in Shortcuts (`shortcuts view <name>`), New Shortcut (opens the Shortcuts app); the name and identifier are stored, the identifier is run when present. *Cancel pause:* a Shortcut marked "Doesn't send or change anything" (`readOnly`) is not an acting step, so it needs no pause before it. *Failures* are plain (didn't finish in time, this Mac doesn't have the Shortcut, Shortcuts isn't allowed, stopped with an error); the raw error text (truncated to 500 characters) goes only to `hotkey.log`. Shortcuts doesn't report its own start-up time, so only the step's total is logged.
- **"Run a Shortcut" and "Your Shortcuts"** (`VoiceYourShortcuts` in `VoiceLaunchCards.swift`, `VoiceYourShortcutsSection`). "Your Shortcuts" is an ordinary list (field `identifier`) inside the mirrored Commands setting, so the matcher (longest name wins), Whisper hints, Teach, Check name and "Did you mean" treat it like People and need no special code. It is machine-derived: only the main Mac (or a standalone Mac) fills it, from `shortcuts list --show-identifiers`, at launch (only when a command uses the list), when the Commands page shows it, and from its Refresh button (`VoiceLaunchActing.fetchYourShortcuts` / `refreshYourShortcuts`; a Mac connected to a main Mac never runs it). `VoiceYourShortcuts.merge` replaces names and identifiers on each refresh but keeps the ways of saying a name that the user added (matched by identifier, else by name) so they persist and sync with the setting; a Shortcut that is gone takes its ways with it; two Shortcuts with the same name (ignoring case and spacing) are one entry, the first; the list is capped at 500. A failed refresh leaves the last list. The Build your own list screen shows it without Edit or remove. The catalog card `run-shortcut` (pattern `Shortcut {which:Your Shortcuts} {words}`, off by default) has a `confirm` step (3 s) then a `runAppleShortcut` whose `shortcutName` and `shortcutId` are references (`{which}`, `{which.identifier}`, `VoiceStep.isTemplate`) that the Core fills in `VoiceLaunchEngine.render` (`VoiceStepRenderer.resolvingTarget`) before the step is deferred, so the target Mac runs the matched Shortcut by identifier with everything said as JSON, and its answer is not typed. Its question when turned on is the cancel pause (default) or "right away": the variant `run-shortcut-now` has no `confirm` and is marked `readOnly` (the existing way to skip the pause), and `VoiceCards.setShortcutMode` keeps exactly one of the two with the same pattern and the user's other ways of starting it. A name that starts with a dash is never passed to `shortcuts`. If the running Mac lacks the Shortcut, the phase-1 plain failure applies.
- **Dictator inside Shortcuts (App Intents).** The standard locally signed build does not advertise these actions: `isDiscoverable` is false and the provider is empty unless `DICTATOR_ENABLE_APP_INTENTS` is explicitly compiled in. Settings explains that availability. Native macOS 27 testing rejected the fixed self-signed certificate at `linkd`’s validated-bundle/Team-ID boundary before `perform()`; a genuine team signature and separate native verification are prerequisites for an enabled deployment. Existing Commands → Apple Shortcuts steps are independent. `Services/Shortcuts/DictatorIntents.swift` (the only file that imports AppIntents) exposes three actions, an `AppEntity` and an `AppShortcutsProvider` (phrases include the app name); they run in the Dictator app itself (no extension, `openAppWhenRun` false), so they use this Mac's own speech path and settings, and Xcode's metadata extraction puts `Contents/Resources/Metadata.appintents` in the bundle with no `project.yml` change (macOS 14 target; nothing newer is used). The work is in `ShortcutsBridge` (`ShortcutsBridge.swift`), which talks to the app through `ShortcutsBridgeServices` (set by `DictatorViewModel`, mocked in `ShortcutsIntentsTests`); an action run before the app has set it up, or without a way to reach the speech path, throws a `ShortcutsBridgeError` whose plain message the Shortcuts app shows. **Dictate** (parameter "Clean up my words", default on) reuses Teach's transcribe-only path: a one-take `VoiceTeachSession` on `EdgeRuntime`'s recorder with the same silence endpointer (2 s of quiet, its countdown) but a 2-minute limit (`VoiceTeachEndpointer.maxSeconds`), driving the dictating badge through `onPhase`/`onTick`; the recording goes to the main Mac's speech path (`teachTranscribe`, over `transcribeRequest` from a connected Mac), then `finishTextForShortcuts` applies the dictionary and, when the toggle is on and the clean-up level isn't Exact, the chosen clean-up model. On a connected Mac that second step is a new optional message pair `textCleanupRequest`/`textCleanupResult` (`CoreHost.cleanUpText`, `CoreConnection.cleanUpText`; an older main Mac ignores it and the action fails with "didn't answer in time"; protocol version unchanged). Nothing is pasted. History is written on this Mac through the normal repository (so `captureDecision` applies) with `source: "shortcuts"` and a new `CaptureSource.shortcuts` (`attribution.captureSource`, shown as "Dictation (from Shortcuts)"); both fields already existed as optional strings, so the store and sync need no migration and an older Mac shows an unknown capture source as a plain dictation. **Run a Voice launch shortcut** takes a `VoiceCommandEntity` (id, card title, opening words; enabled commands only, `EntityStringQuery`) and optional "words". The sentence is the command's trigger words plus the words; `VoiceLaunchEngine.plan` runs over a copy of the config holding only that command (so no other command can win), and `VoiceLaunchExecutor.run` executes the plan on this Mac, cancel pause included (`answered:` reports each Shortcut answer). It returns the last non-empty answer, else the plan's main text; a cancel or failure throws with the alert's words. The given words are used as typed: no clean-up and no dictionary, since they are text, not speech. **Clean up text** requires a chosen clean-up model (`cleanupTarget`), then runs the same dictionary replacements and `cleanUp` as dictation, on the main Mac; a model that errors leaves the words as they were, as in dictation. Its description says it uses an AI model.
- **Acting steps** (`VoiceLaunchActing.swift`, run by `VoiceLaunchExecutor`). Everything outside the process is injected through `VoiceLaunchServices` so tests use mocks. `confirm` shows the rendered summary in the progress notice with "Sending in N s. Esc to cancel." (`VoiceLaunchCountdown`, default 3 s). Esc comes from the existing hotkey tap (`VoiceLaunchEscapeWatch.fire()` in `HotkeyService.handleEvent`, plus a local monitor for Dictator's own windows), so it needs no new permission. Cancelling stops the chain, puts the plan's main text on the clipboard and shows a plain notice (`Result.cancelled`, no error sound). `pressKey` (return, cmdReturn, tab, escape) posts a tagged CGEvent to the frontmost app and refuses when the app the chain opened isn't in front. `runAppleShortcut` is described under the Apple Shortcuts bridge above. `webhook` POSTs the JSON body (`VoiceLaunchEngine.webhookBody`) to an http or https address with a 10 s timeout and no custom headers; anything but 2xx is a failure. `appendToFile` adds `yyyy-MM-dd HH:mm:ss | text` to a user-chosen file (created 0600 if missing; failure if its folder is missing). A step's failure or a cancel means later steps never run. `appendToFile` refuses hidden files and folders, Library and system paths, on the resolved path, in validation and again at run time. Spoken words given to a terminal command stay one argument and never start with a dash, so they can't become a flag. A confirmation pause is bounded again on the Mac that runs it, because `insert.launch` skips validation there.
- **Aliases (Teach and the one-click fix).** The speech recognizer mishears names ("Noam" becomes "norm"), so the fix is data, never fuzzy matching at run time. A list entry's extra names are its aliases; a command has `triggerAliases`, other spellings of its leading fixed words (the trigger). `bestMatch` accepts the real trigger or any alias exactly, after normalizing, and scores every spelling as the real words. Both live in the `voiceLaunchJSON` mirrored setting; a setting saved before `triggerAliases` existed decodes with none, and the field is left out of the JSON while empty. An alias may not equal another command's trigger or alias (`VoiceLaunchConfig.validate`), or another entry's name or alias in the same list (`addEntryAlias`, Teach). All the rules are in `VoiceLaunchAliases.swift`.
- **Near misses.** `plan(for:in:)` returns `PlanResult.nearMiss(VoiceNearMiss)` (pure, in `VoiceLaunchNearMiss.swift`) when nothing matched but the words were close. Entry near miss: a command's fixed words matched and a list slot found no entry; it names the command, slot and list, the words heard at the slot (one word, or also two when a text slot follows, or up to the next fixed word) and up to three entries ordered by simple edit distance on normalized text. The ordering only orders suggestions; nothing is saved without a click. Trigger near miss: no command matched at all; it carries the first one or two words. The Core attaches the near miss to `VoiceCommandDelivery` (`nearMiss`, optional on the wire; an older Mac ignores it and types the words with the old notice). On a current Mac, both entry and trigger near misses type nothing: the transcript goes on the clipboard and `VoiceNearMissNoticeController` shows an interactive notice on the target Mac ("Heard “norm” — who did you mean?"). Choosing a name calls `VoiceNearMissFix.fixEntry` (adds the alias with the same conflict rules, then plans the same transcript again and runs it, confirm steps included); a trigger near miss offers "Make “…” another way to say…" with a picker of commands (`fixTrigger`, no re-run). Both write through `AppSettings.updateVoiceLaunch`, so they reach every Mac by the settings mirror. "Try it" shows the same fixes (`VoiceNearMissFixView`). The re-run uses the words as spoken (no clean-up of the clean-up slot).
- **Teach.** Each list entry and each command trigger has a Teach button (`VoiceTeachSheet`). The person records four takes (the Record button; a take ends after two seconds of quiet or six seconds in all, `VoiceTeachEndpointer`; a "Stopping…" bar and the seconds left show while it records); audio is accumulated only then, through the Edge runtime's existing 16 kHz mono recorder (`VoiceTeachRecording`, `VoiceTeachSession`). Each take goes through `DictatorViewModel.transcribe(rawOnly: true)`: the same speech path as dictation (the Core's speech sources in order, the same Whisper hints as command mode) but with no clean-up, no dictionary replacements, no paste and no history; the audio is dropped. On a connected Mac the request is `EdgeMessage.transcribeRequest` (the header, then one binary frame) answered by `CoreMessage.transcribeResult`; both are new message types an older peer ignores, and `EdgeProtocol.version` stays 2. On the main Mac `CoreHost.transcribeForTeach` is the same function. `VoiceTeach` extracts the alias: with a real phrase ("WhatsApp Noam") and its fixed words heard, the alias is the words at the name's place; otherwise the whole transcript is shown for the person to tap the words that are the name; for a trigger the whole heard text is the candidate. New distinct candidates are pre-checked, ones equal to the name are hidden, and conflicts are shown in words and can't be saved.

Teach, Check name and Shortcuts Dictate reserve this Mac's microphone until their take ends or is cancelled. Another take or dictation cannot replace their buffers, and stale stop/cancel messages cannot end a different owner's recording. While reserved, the Mac reports its microphone unavailable for new broker sessions. A racing `capture.start` gets a session-scoped `capture.failed`; the main Mac accepts it only from that session's microphone owner and only before audio has been handed to transcription. This new message is ignored by older peers without changing the protocol version.

**Background Commands.** Optional `VoiceStep.background` runs a Terminal action on the Mac executing the plan, through the injected `runProcess`, without a Terminal window. It is an acting step requiring a command and cancel pause. The unchanged command allow-list is rechecked at run time; `/bin/zsh -f -c` receives folder and spoken text as positional arguments, with the existing leading-dash protection. The shell is noninteractive, stdin/stdout use `/dev/null`, and only basic user/locale values and a fixed search path enter its environment. Timeout, Esc and task cancellation kill its process group, including children. `timeoutSeconds` defaults to 60, with a range of 1...600. A plain failure alert shows exit status and a bounded stderr snippet, keeping words on the clipboard; diagnostics contain status and duration only. Older Macs ignore the flag and run visibly. No new step kind, store or protocol version is introduced.
**Commands limited to apps.** `VoiceCommand.onlyInApps` is a mirrored list of up to 20 bundle identifiers; empty means everywhere. `HotkeyService` samples the pressing Mac's frontmost app before showing UI and sends optional `appBundleId` on the existing `shortcut.mode` message. The broker retains each presser's sample through settling, uses the initiator's sample, then consumes it for matching. It never enters history or logs. Missing context from older Macs, Try it or Apple Shortcuts means unknown: only global commands qualify. Among equally matching phrases a scoped command beats a global command; equally fitting scoped commands still tie. Validation permits disjoint scopes and global fallbacks, but rejects overlapping scoped duplicates. Near-miss suggestions carry eligible command IDs rather than the app; choosing a missing name replays only that chosen command.
**Starting Commands without speech.** `VoiceCommandTriggerController.run` checks enabled state and required spoken parts, renders through `VoiceLaunchEngine` with empty slots and no transcript, then calls the local executor with `.keyboard` or `.otherApp`. Both main and connected Macs read `AppSettings.voiceLaunch`, already populated by `CoreSettingsMirror`; there is no second configuration. `WorkspaceHotkeyCoordinator` observes both mirrored settings and refreshes the existing Carbon registry. Commands and routines cannot share keys, and recording a key suspends both. Pause (`isPromptCapturePaused`) stops typed-history capture, not commands: keyboard starts run through it, as routines do, and only `dictator://` links wait for it to end. Links arrive through `AppDelegate.application(_:open:)`, and one that launches the app is held until startup finishes.

`dictator://run?command=<exact name or id>` requires per-command opt-in. Only the saved command reaches rendering; extra query parameters are ignored. Acting or Terminal steps require a fresh Allow/Cancel dialog with the saved name and actions. One start owns the dialog/execution lock, and links are limited to one attempt per two seconds. Malformed links are ignored without logging their contents. SwiftUI receives URLs; the controller refuses them before `applicationDidFinishLaunching` and in Debug or non-production bundle IDs. No stored keys, step kinds or protocol versions change.

**Command files.** `CommandFile` transforms the version-1 `.json` envelope (`dictatorCommands`, `commands`, `lists`) separately from stored settings. Export strips command IDs and launch permissions, includes list entries only by explicit choice, and blanks whole values containing paths or addresses unless included. Commands offers bounded import and a review sheet; unknown step kinds or higher formats fail before reaching settings. Imported commands get new IDs, stay off and lose keyboard/other-app permissions. Lists merge by normalized name without replacing overlapping entries. Confirmation validates the combined candidate against current settings and uses `updateVoiceLaunch`, including on a connected Mac. Existing validation requires missing values and phrase clashes to be resolved in review before saving; no command runs during import.
**Recent commands (per Mac).** `CommandActivity` records each `VoiceLaunchExecutor.run` outcome once, keeping 50 in `Application Support/Dictator/recent-commands.json` with background, atomic file writes. Only command identity/name, time, trigger, outcome and audited fixed failure titles are saved. Plans, spoken values, app/window names and arbitrary errors are excluded. History off or Pause suppresses new records. Home shows five; Clear removes the file, as does uninstall's optional data removal. No in-app delete-all-history action exists. The log is outside replication, settings, SwiftData and Datasets. Run Again retains the resolved plan only in memory, reuses its pauses on this Mac (including connected Macs), and clears on Pause. Welcome optionally adds safe catalog starters through `updateVoiceLaunch` only with no existing commands, reuses Try it matching and observes success even with history off.

## Typed history

Optional and off for new users. When on, Dictator saves what you type in chosen places, next to your dictation.

- **The decision** is made in one place, `AppSettings.captureDecision(for:modality:)`, against `SurfacePolicy` v2 (per tool: typed and voice switches, plus rules for exceptions and `scrub_secrets`). `HistoryRepository.record` checks it again and stores why the row was saved. The policy lives in the app and is mirrored between Macs.
- **Tools, host apps and connectors** come from `shared/tool-catalog.json`; user additions go in `~/Library/Application Support/Dictator/custom-tools.json`. Successful custom-tool writes publish an observable catalog snapshot. Removing a chosen custom tool also removes only its per-tool surface-policy entry through the existing shared-settings mirror; other Macs’ unknown tool IDs and explicit exception rules are retained. Write errors keep the previous catalog and policy visible. Existing history is unchanged.
- **Capture** (`Services/Capture/`):
  - `TypedPromptCapture` reads the keyboard and decides at submit, using `SurfaceResolver` (process table, tmux, ssh, editor focus, browser URL). It holds no keystrokes at all while no typed place is on. A focused password box or secure input discards the draft. A browser has one draft per process, across every field and tab, so there only the text box read at submit counts as a prompt, unless the user chose to save everything.
  - Coding tools can instead be captured exactly by a hook in the tool's own settings (`shared/connectors/dictator-capture`, a POSIX shell shim) or by reading the tool's transcript files.
  - Permission to save is mirrored; capture methods, hooks and the shim belong to each Mac. `PromptCaptureCenter` checks local signatures and setup at launch, after local or mirrored policy/method changes, and every 300 seconds. An enabled, locally installed tool needs setup when its chosen (or recommended) hook or shim is missing; tools that are off or absent do not raise a banner. A chosen history-file or keyboard method is preserved. An unchosen non-hook connector still needs the initial method setup.
  - Home, Datasets and Typed History show the same plain setup banner naming the affected tools and this Mac. **Set up** is the explicit local action that runs existing connector setup, keeps configuration backups and retains a result for every attempted tool, so later successes cannot hide failures. At launch, an existing shim is updated when a tool uses the hook method; matching shim versions are left untouched. Status checks never write tool configuration or recreate a deleted shim. Removing a hook or shim stops that connector until the user sets it up again; external repairs are reflected without relaunching. Typed history remains off until the user opts in.
  - Servers reached over SSH get the same hook, installed and collected over the user's own SSH (`RemoteCaptureService`). Nothing listens on the server.
  - `PromptRecorder` removes duplicates across sources and, when `scrub_secrets` is enabled, replaces recognized secret formats with `[redacted]`. Arbitrary passwords in ordinary prose are not reliably detected.

## Datasets

Datasets prepares saved prompt history for whatever analysis tools the user chooses. Dictator performs no analysis, inference, advice or automatic agent runs.

- **Screen.** The sidebar calls it *Datasets*. Its *New* tab puts the common choices first (time range, Sent to, input, text). Everything else is folded behind a one-line summary of its current state: more filters, cleaning and privacy, format and details, and the raw file. The preview shows prepared prompts and “Matched X, took Y” counts before and after the limit. **Create dataset** saves a snapshot. The bar then offers **Copy prompts**, **Save as one file…**, **Copy location for a local agent** and a menu with Copy path, Show in Finder, save a copy elsewhere, attach a report, run a local tool and delete. The ready state lasts until the user changes a choice (`DatasetStore.editRevision`); new history arriving does not clear it. The *Saved* tab lists snapshots with the same actions. Datasets uses plain language in both voice modes.
- **Chat handoff.** `DatasetHandoff.render` is a pure renderer of the saved prepared records and manifest. `DatasetStore.prepareHandoff` loads the integrity-checked canonical `records.json` and renders off the main actor, without rereading history. **Copy prompts** copies the complete self-contained text; **Save as one file…** uses `NSSavePanel` with the dataset name and `.md` extension and writes exactly the same UTF-8 text for upload to a chat app. The text retains the existing brief's opening, date range, data-not-instructions warning and applicable redaction note, then compact JSON Lines in chronological order with date (ISO 8601), input, optional destination, optional project basename and prepared text, ending in `Task:`. JSON encoding escapes prompt newlines; nil fields are omitted. With context excluded, only date, input and text remain. It has no folder path or file list. Size is shown as a prompt count and approximate tokens (character count divided by four, rounded up), with no agent/model recommendation. Above the named 200,000-character paste threshold, saving a file becomes primary and a line explains that it is too long to paste reliably; copying stays secondary. The separate `DatasetPackage.agentBrief` retains the folder/file brief as **Copy location for a local agent**. Neither handoff runs anything or chooses a provider.
- **Where prompts went.** `DatasetDestinationResolver` gives each row one destination from what it recorded, using the tool catalog. In order: the recorded tool; the tool that owns the app (`com.openai.codex` is ChatGPT, the merged app), except editors, which host many things; the tool that owns the website. Failing that: *Terminal or agent app, tool not recorded* for terminals, `terminal://` destinations, multiplexers (Herdr, tmux, zellij) and agent apps that run several tools without recording which (T3 Code), or the app under its catalog or readable name. *Sent to* groups these by vendor (all Anthropic, then Claude and Claude Code), then terminals, other apps and not recorded, with counts. *Saved by* (dictation, typed history, connected AI tool, imported) replaces the separate capture-method and origin filters. Filters with one value in history (project, computer, remote host, session) are hidden unless set.
- **What’s being saved.** Datasets has a collapsed “What’s being saved” disclosure inside its card. It lists switched-on tools installed on this Mac or with saved dates, with their selected or recommended capture method and observed state on this Mac; other switched-on tools are summarized in one count. Latest prompt dates are grouped by tool and recorded originating computer from the full `DatasetStore.rows`, independent of dataset filters, including replicated and imported rows already in history. Existing Datasets app/website attribution is used when a row has no explicit tool; an unidentified terminal never implies a tool. Missing computer IDs remain “Computer not recorded”; no dates are invented for an empty history. The section contains no prompt text, recency thresholds or assessment, and reads no tool logs or other Mac’s store.
- **Read locally.** `DatasetStore` reads plain `DatasetRow` values from this Mac's history through `HistoryDatasetStore`. It loads only when opened and refreshes after local history changes. Replicated rows are included when present; no other Mac's store or tool transcript logs are read for this screen. Typed history remains optional and off by default.
- **One selection.** `DatasetQuery` ANDs inclusive date/time bounds, input, saved-by, captured/imported status, website, remote host, full project directory, originating computer, exact session ID, stored word count and a text condition (contains, all/any whitespace-separated terms, or case-insensitive regular expression). **Sent to** accepts several destinations or `vendor:` keys with any-of semantics. The optional `destinations` list replaces the legacy single `destination` when present; old saved queries still decode. Advanced filters include **Not sent to**, using the same destination choices (any match rejects a row), and **Leave out text**, which rejects any whitespace-separated term as a case-insensitive substring. Exclusions win over inclusions. All text conditions inspect stored text before preparation. **Take** defaults to All, or limits to Newest N, Oldest N or Random N after every filter and before cleaning. N must be positive. Random sorts ascending on SHA-256 of UTF-8 seed + newline + lowercased row UUID, with UUID tie-breaking; the query stores the seed and **Shuffle** replaces it. A missing seed uses `0`. Every result is chronological with UUID tie-breaking, including random samples. Preview and saved datasets use the same selection. New stored query fields are optional, and reset/saved selections include them. Invalid filters clear the preview and disable creation. There are no inferred sessions or implicit date ranges.
- **Prepare a copy.** `Dataset` normalizes line endings and optionally trims surrounding whitespace, removes empty prompts, removes exact repeats within the same recorded place/project/session/computer/remote host/input, hides recognized credential patterns using `SecretScrubber`, and excludes context or timing metadata. Missing session IDs leave deduplication bounded by the other recorded fields; duplicates keep the earliest entry. Redaction happens after deduplication and applies to text, included metadata, the package name and the manifest query, including excluded text and destination lists. It does not anonymize ordinary prose or reliably hide arbitrary passwords. History itself is never modified. Exported word counts are recomputed from prepared text; the original stored count, original modality, source, capture context and inference duration are also available when applicable.
- **Package.** JSONL, JSON and CSV share the exact prepared records shown in the preview. Every package also includes canonical `records.json`, `manifest.json` and `SCHEMA.md`. The versioned manifest records the selection, preparation choices, matched/taken/exported/removed/redacted counts (matched before the limit, optional `takenRecords` after it and before cleaning, exported after cleaning), date range, stable record IDs in the data and SHA-256 hashes for the data file and canonical JSON. Readable dates are ISO 8601 UTC at second precision; numeric Unix-second fields preserve subsecond record timestamps and filter bounds. Local saved selections preserve exact filter bounds. Absent JSON fields and blank CSV fields mean unknown or excluded. CSV quotes multiline values and prefixes formula-leading values with an apostrophe; JSON preserves the text literally. Filter values can be omitted from the manifest independently of per-record metadata. A query containing a redacted credential is descriptive and cannot necessarily be rerun verbatim.
- **Local archive.** Saving or exporting creates an atomic snapshot under `~/Library/Application Support/Dictator/Usage/<UUID>/`; later history changes do not alter that snapshot. Export copies the package to a user-chosen folder and never overwrites an existing package. Reports selected by the user are copied into that package's `Reports/` folder without interpretation. A package is independent of history retention/deletion; delete it separately from Datasets › Saved when no longer wanted. Saved selections, CLI setup, known computer names and archive paths belong to this Mac (`Usage/preferences.json`), not the shared settings mirror.
- **Optional CLI delivery.** From an archived package, the user chooses an absolute local executable, literal arguments (one per line), and optional instructions. An explicit Run action starts it using Foundation `Process`, with the package as working directory. Standard input is a JSON envelope with `instructions`, `manifest`, and the canonical prepared `records`, regardless of export format. No shell interpolation, provider/model selection, authentication, installations, remote execution or automatic reruns are performed. Existing user credentials and environment are inherited; the executable's directory and standard local CLI locations are added to PATH. The user-selected CLI controls what happens to the data. Input, invocation, exit code and complete stdout/stderr are stored under `Reports/CLI-<UUID>/`, including nonzero exits and cancellation after startup. File-backed I/O writes output into the archive while the CLI runs and avoids pipe deadlocks; app teardown cancels the directly launched process. Before sending or exporting, both data hashes are verified. Cancellation terminates the directly launched process; a CLI that launches its own descendants is responsible for them.
- **Import.** `Services/Import/` reads ChatGPT and Claude exports, Claude Code and Codex logs, Gemini Takeout, Wispr Flow (read-only), text and JSONL. The existing preview/deduplication/tombstone-aware import and batch removal are retained in Datasets. Imported history is added only after explicit confirmation.
