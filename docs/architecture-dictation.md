# Dictation internals

[Architecture overview](architecture.md) · [Development](development.md)

## One dictation, start to finish

1. **Key down** on the Mac you're using (`HotkeyService`, an event tap on the dictation keys, Right ⌥ unless you chose others). That Mac is the initiator unless another Mac reports the same gesture during a short settling window. The broker waits up to 150 ms when another Mac has the freshest focus claim, or when the pressing Mac has no microphone, no chosen recorder is available, and another connected Mac could record. Matching presses from multiple Macs are evidence of one keyboard shared over Universal Control; focus claims then choose only among those pressing Macs. A press from one Mac alone belongs to that Mac, even if a distant Mac has an older pointer claim. Independent keyboards and Macs in different places use this same rule.
   A character typed while a press is settling sends `press.abandon` (`EdgeMessage.pressAbandoned`, a new optional message older main Macs ignore), which can only drop a press still settling and never touches a running recording.
2. **The main Mac starts a session** (`SessionBroker`): the recording Mac is the connected microphone chosen under Settings › Your Macs › Mac that records, otherwise the initiator if it has a microphone, otherwise another Mac that reported the same press. It never silently borrows a microphone from a Mac that did not report the press. If only another Mac has a microphone, the initiator gets an alert asking the user to choose one in Your Macs; no session starts. If none has a microphone, it gets the existing microphone alert. The target starts as the initiator. Only pointer claims received from the session's start onward, or otherwise keystroke claims from Macs that reported the press during this session, can move it. Earlier claims cannot move the words to a distant Mac. The dictating badge shows on the target. A press rejected while processing or inserting, or because its gesture does not match the recording mode, gets a notice on the pressing Mac saying nothing was recorded, at most once per Mac every two seconds. Ten seconds before the 120 s time limit the main Mac sends `session.countdown` (an optional message older Macs ignore) to the target and the initiator; each ticks softly and the badge shows "Stopping in N…" until the recording ends. When the watchdog stops capture, optional `SessionStateUpdate.recordingLimitReached` marks the session without changing protocol version 2. The initiator shows one notice that recording stopped at 2 minutes and the words were kept; audio upload, transcription and insertion continue normally. Repeated state broadcasts do not repeat the notice.
3. **Recording.** After microphone access is allowed, the audio engine runs from setup, including while idle; macOS can show it as in use. The tap drops buffers unless `isCapturing` is true, so idle audio is neither accumulated nor checkpointed. Holding the key, tap mode and explicit recording actions begin capture. The mic owner records 16 kHz mono float PCM, writing a checkpoint to disk as it goes (`RecordingCheckpointWriter`), and sends it to the Core as one binary frame on key up. Once capture stops, a 30-second upload deadline prevents missing audio from blocking later dictations. Invalid headers and incomplete frames fail with a recovery alert; the recorder keeps its checkpoint. Duplicate uploads cannot start recognition twice.
4. **Speech to text.** The Core tries the speech sources in the order chosen in Settings › Your Macs (`SetupRouting.speechSources`), moving any it last found unreachable to the end:
   - a **speech server** (`server/`, `POST /transcribe`), which also cleans up unless clean-up runs elsewhere, or
   - a **speech model in Dictator on one of the Macs** (`LocalSpeechService`): Whisper through WhisperKit, or Apple's recognizer. For another Mac, the Core sends `speech.request` plus the audio frame and gets `speech.result`.
5. **Clean-up.** Unless the user chose "Skip AI clean-up", the words go through the clean-up prompt (`CleanupPrompt`, a verbatim port of the server's) on the chosen Mac's Ollama (`cleanup.request` → that Mac calls Ollama on 127.0.0.1). Before the model runs, explicit punctuation commands become punctuation and line breaks; a correction marker followed by the immediately preceding clause’s first two words replaces that clause; older clauses are never searched. Other corrections stay with the model. If the output reads like a reply, drops line breaks, loses more than one fifth of distinct source words overall or within a sentence, or removes a spoken English/Hebrew script, the prepared transcript is used. Each spoken line goes to the model alone, because the model drops line breaks when it sees them; a rejected line falls back by itself and the others keep their clean-up. `CleanupPrompt.run` and `polish_text` do this, in the same order. A Hebrew prefix split from its word can be rejoined without counting as a lost word. "Skip AI clean-up" bypasses AI rewriting; speech recognition can still change fillers. Dictionary replacements are applied in every path.

   "Polish the text" (`RefineLevel.polished`) swaps in a prompt that may reword (`polishedSystemPrompt`), so the rule above can't apply. Its own check (`isPolishFaithful`, shared cases in `shared/polish-guard-fixtures.json`) accepts changed words but rejects lost sentences, translation, changed numbers and reworded dictionary terms. A rejected polish gets one ordinary clean-up, so a failure costs a second model call rather than the punctuation. The check compares words, so it can't see a changed Hebrew verb form: on the default model a synthetic sentence had its addressee's person changed despite the prompt's rule against it. The history comparison is how a user sees that. Workflows and the Shortcuts action stay at ordinary clean-up, because their words often go on to be matched or sent. A connected Mac recovering a recording finishes it through the main Mac at ordinary clean-up too.
6. **Typing.** The target pastes the text (`PasteService`, ⌘V with the clipboard restored). If it can't, the text stays on the clipboard and an alert says so. In Finder, the original text-field snapshot must still be the directly focused editable AX element in the current Finder process before any paste event; otherwise text stays on the clipboard, avoiding Finder’s text-clipping file action. Unreadable fields in other apps retain the existing best-effort paste. Before pasting, the text is joined to what's already before the caret (`InsertionSeam`): a leading space when needed, and a common first word lowercased when the text before it is mid-sentence. Only the new text changes; fields that expose no text get it as it is.
7. **History.** When history policy allows saving, the Core records the engine’s `heardText` alongside the final inserted text with where it landed, which models ran and how long it took (`recordHistory`). `polishModel` says which model was asked; `cleanupLevel`, `cleanupOutcome` (`CleanupOutcome`) and `cleanupMs` say what was chosen, what really happened and how long it took. A speech server reports these in `X-Polish`, `X-Polish-Level` and `X-Polish-Ms`; one that sends no level ran an ordinary clean-up, so a Polished request counts as a fallback. Home shows this as a tag on each row (`CleanupStamp`), and Settings › Dictation shows one line for the last 50 (`CleanupSummary`). Both are counts of what happened, with no advice, and nothing leaves the user's Macs except by the usual sync between them and Datasets exports. A save error retains the recording and reports a failure to all peers, including peers asking for the outcome after reconnecting; their recovery copies are not deleted as if saving had succeeded.

If anything fails, the Mac you pressed the key on shows a plain-language alert (`DictationAlert`). The recording checkpoint is kept and listed under History & Privacy › Needs your attention, to turn into text later (`RecoveryService`).

An empty recognition result only discards audio that passes the same conservative silence check used by recovery. If an audible chunk returns no words, the whole recording stays recoverable and no partial transcript is pasted. Ordinary pasting has a 20-second response deadline; commands add their configured pauses, text-field waits, Apple Shortcut limits and time for app opening and web requests.

## Speech and clean-up models

- **Whisper through WhisperKit** runs in the app on any Mac (`Services/Speech/LocalSpeechService.swift`). Models download to `~/Library/Application Support/Dictator/SpeechModels`; their ids look like `whisperkit:openai_whisper-large-v3-v20240930_turbo`. Settings › Dictation › Languages you speak (`SetupRouting.languages`) controls language selection. With multiple choices, the allowed language with the highest detector probability is selected; a single choice is used directly. An empty list or detector failure falls back to unrestricted detection. Normally one decoding language is used per recording, even with several languages selected. That metadata does not prove transcript accuracy or every language spoken; mixed-language words can be changed or omitted. Dictionary words are passed as prompt tokens.
- **Apple speech recognition** (macOS 26+) uses `SpeechTranscriber` where it covers the language and `DictationTranscriber` otherwise (the only one with Hebrew). Ids look like `apple:he-IL`; macOS downloads the assets.
- **Clean-up models** run in Ollama on the Mac they're installed on. Dictator never exposes Ollama on the network; other Macs reach it through Dictator's own connection. `RefineLevel` offers `exact`, `medium` and `polished`. `polished` is stored and sent as the retired value `strong`, which older Macs normalize to `medium` and older speech servers treat as ordinary clean-up, so choosing it needs no protocol change. A pre-existing saved `strong` therefore loads as Polished. The retired `light` still normalizes to `medium`; unknown wire values are still rejected. `customSystemPrompt` stays in the mirrored settings format for older Macs; nothing reads it.
- **Downloads** for another Mac go through the Core (`model.pull`, progress in `model.pull.progress`). The models offered, with the memory each needs, are in `shared/model-catalog.json`; any Ollama tag can be typed.
- **The speech server** (`server/`) runs Whisper (MLX) and Gemma through Ollama on one Mac. Its clean-up prompt and faithfulness check are the source for `CleanupPrompt`; `CleanupPromptTests` uses the same cases as `server/tests/test_polish_guard.py`.
- **Speech authentication.** Server startup loads `DICTATION_TOKEN_FILE` (default `~/Library/Application Support/Dictator/speech-server.token`), atomically creating a random 0600 file only if missing. Empty or unreadable files prevent startup. `/transcribe` and `/warm` require a Bearer key compared with `hmac.compare_digest`; a missing or wrong key returns an empty 401 before processing. `/health` remains open and never reveals the key. The app only reads the server-owned local file through `LocalSecret` and never creates or overwrites it. Settings › Advanced › Speech server key saves a pasted remote key atomically in the separate 0600 `speech-server-remote.token`. No migration is needed because pasted keys have not shipped yet. Key selection is a pure function of the request host, this Mac’s interface addresses from `getifaddrs`, and the two keys: loopback or an own interface address uses the local key only; another host uses the remote key, falling back to the local key. In particular, `http://100.101.102.103:7878` uses the local key on the Mac owning that address. The environment override applies only to the server-owned local key. Neither key enters `UserDefaults`, history, logs or the settings mirror. All remote servers, including backups, must accept the same remote key. A key alert for live dictation initiated on another Mac points to Settings › Advanced on the main Mac, naming it when known, and has no local action button; local dictation and direct recovery keep the button.
- **Speech address safety.** The pure `SpeechEndpoint.validated` rule builds on `ServiceEndpoint` without changing its other callers. HTTPS accepts any host; HTTP accepts only loopback, `100.64.0.0/10`, `fd7a:115c:a1e0::/48` and `.ts.net` hosts, using parsed IP bytes for range checks (including IPv4-mapped IPv6). Advanced validates main and backup addresses. Warm-up, recognition, reachability and health inventory requests all enforce the same rule; speech redirects are refused so neither audio nor the key is forwarded. Invalid saved addresses are retained for correction and produce an explained dictation failure rather than sending audio. The source chain still tries backups; if all fail, a key/address problem takes precedence over later outages and travels in the existing encoded `DictationAlert`. Recovery retains the alert and audio and offers the same Advanced action. Older peers can still show its plain message even if they do not recognize the action; the protocol version is unchanged.
- **Server archives are opt-in.** `DICTATION_KEEP_TAKES` defaults to `0`, saving no new audio or transcripts on the server. Above zero, its existing rolling WAV/JSON archive stores audio and text regardless of the app's history setting. Disabling it leaves existing takes alone and adds no cleanup. App recovery checkpoints retain their separate failure-recovery behavior.
- **Deployment order.** Install the updated app on requesting Macs first, then restart the speech server. The updated app keeps working with older servers that ignore the header; older apps cannot authenticate after the server upgrade. Once the server creates its key, same-Mac requests read it automatically. Add that key in Advanced on other requesting Macs, including Macs doing direct recovery.
- **Models unload after an idle period.** The speech server starts with nothing loaded. At key down on any Mac, the Core sends `POST /warm` to the server the dictation will use (`prepareModelsForDictation`), with the refine level that server will get, so the models load while the user speaks. Gemma is left out when the words are typed exactly as spoken or cleaned up elsewhere. A request waits for a load in progress. After five idle minutes (`DICTATION_IDLE_UNLOAD_S`), the server drops Whisper, and Ollama drops the clean-up model through a finite `keep_alive`; the app's own Ollama calls use the same window. The server caps MLX's buffer cache and runs clean-up with a text-only copy of the model (`<model>-text`, without the unused image/audio part). `/health` never loads anything and reports `ok` while the models are unloaded.
