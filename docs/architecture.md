# How Dictator works

This is the reference for how the app is put together. The rules for changing it are in [AGENTS.md](../AGENTS.md).

## Names

| Product name | Code name |
|---|---|
| Workspaces | `WorkspaceLaunch*`, `workspaceLaunch` |
| Datasets | `Dataset*`, `.datasets`, `Views/Datasets`, `Services/Datasets` |
| Commands | `VoiceCommand`, `VoiceCommandCatalog`, `VoiceCommandEditor` |
| Main Mac | Core |
| Connected to a main Mac | Edge |

Stored keys, wire fields and paths retain their historical names: `workspaceResetJSON`, `shortcuts`, `shortcutMode`, `shortcutId`, `shortcutName`, `shortcut.mode`, `insert.shortcut`, and the `Usage` archive folder. Explicit coding keys preserve these names; Sidebar raw values remain unchanged. Apple Shortcuts bridge and App Intents identities keep their Shortcuts names. Dictionary usage counters are unrelated to Datasets. SwiftData model and attribute names are unchanged.

Commands = Voice launch in code; Workspaces = Workspace launch in code. Product copy uses Commands and Workspaces; stored names stay unchanged. Legacy App Intent titles and Siri phrases remain unchanged pending native checks with saved Apple Shortcuts.

## Macs and roles

Every Mac runs the same app. Each install has a role (`CoreRole`), shown in Settings in plain words:

| Role in code | In Settings | What it does |
|---|---|---|
| `standalone` | On its own | One Mac, nothing shared. |
| `core` | Main Mac | Keeps the main copy of history, the dictionary and shared settings; other Macs connect to it; runs every dictation's session logic. |
| `edge` | Connected to a main Mac | Records, types and keeps its own copy of history; the main Mac decides what happens. |

The main Mac (the Core) listens on its Tailscale address, port 7880 (`EdgeProtocol.corePort`), and only accepts peers in Tailscale's range (100.64.0.0/10). Each connected Mac (an Edge) opens one WebSocket to it and says `hello` with a pairing token. The protocol is JSON text frames plus binary frames for audio (`Models/EdgeProtocol.swift`, `EdgeProtocol.version` 2). Tailscale encrypts and authenticates the link; there is no TLS on top.

The Core also runs a local Edge for itself, so a single Mac and a group of Macs use the same code path (`CoreHost`, `SessionBroker`). A connected Mac that loses its Core falls back to working on its own until the Core is back.

## One dictation, start to finish

1. **Key down** on the Mac you're using (`HotkeyService`, an event tap on the dictation keys, Right ⌥ unless you chose others). That Mac is the initiator unless another Mac reports the same gesture during a short settling window. The broker waits up to 150 ms when another Mac has the freshest focus claim, or when the pressing Mac has no microphone, no chosen recorder is available, and another connected Mac could record. Matching presses from multiple Macs are evidence of one keyboard shared over Universal Control; focus claims then choose only among those pressing Macs. A press from one Mac alone belongs to that Mac, even if a distant Mac has an older pointer claim. Independent keyboards and Macs in different places use this same rule.
   A character typed while a press is settling sends `press.abandon` (`EdgeMessage.pressAbandoned`, a new optional message older main Macs ignore), which can only drop a press still settling and never touches a running recording.
2. **The main Mac starts a session** (`SessionBroker`): the recording Mac is the connected microphone chosen under Settings › Your Macs › Mac that records, otherwise the initiator if it has a microphone, otherwise another Mac that reported the same press. It never silently borrows a microphone from a Mac that did not report the press. If only another Mac has a microphone, the initiator gets an alert asking the user to choose one in Your Macs; no session starts. If none has a microphone, it gets the existing microphone alert. The target starts as the initiator. Only pointer claims received from the session's start onward, or otherwise keystroke claims from Macs that reported the press during this session, can move it. Earlier claims cannot move the words to a distant Mac. The dictating badge shows on the target. A press rejected while processing or inserting, or because its gesture does not match the recording mode, gets a notice on the pressing Mac saying nothing was recorded, at most once per Mac every two seconds. Ten seconds before the 120 s time limit the main Mac sends `session.countdown` (an optional message older Macs ignore) to the target and the initiator; each ticks softly and the badge shows "Stopping in N…" until the recording ends. When the watchdog stops capture, optional `SessionStateUpdate.recordingLimitReached` marks the session without changing protocol version 2. The initiator shows one notice that recording stopped at 2 minutes and the words were kept; audio upload, transcription and insertion continue normally. Repeated state broadcasts do not repeat the notice.
3. **Recording.** After microphone access is allowed, the audio engine runs from setup, including while idle; macOS can show it as in use. The tap drops buffers unless `isCapturing` is true, so idle audio is neither accumulated nor checkpointed. Holding the key, tap mode and explicit recording actions begin capture. The mic owner records 16 kHz mono float PCM, writing a checkpoint to disk as it goes (`RecordingCheckpointWriter`), and sends it to the Core as one binary frame on key up. Once capture stops, a 30-second upload deadline prevents missing audio from blocking later dictations. Invalid headers and incomplete frames fail with a recovery alert; the recorder keeps its checkpoint. Duplicate uploads cannot start recognition twice.
4. **Speech to text.** The Core tries the speech sources in the order chosen in Settings › Your Macs (`SetupRouting.speechSources`), moving any it last found unreachable to the end:
   - a **speech server** (`server/`, `POST /transcribe`), which also cleans up unless clean-up runs elsewhere, or
   - a **speech model in Dictator on one of the Macs** (`LocalSpeechService`): Whisper through WhisperKit, or Apple's recognizer. For another Mac, the Core sends `speech.request` plus the audio frame and gets `speech.result`.
5. **Clean-up.** Unless the user chose "Skip AI clean-up", the words go through the clean-up prompt (`CleanupPrompt`, a verbatim port of the server's) on the chosen Mac's Ollama (`cleanup.request` → that Mac calls Ollama on 127.0.0.1). Before the model runs, explicit punctuation commands become punctuation and line breaks; a correction marker followed by the immediately preceding clause’s first two words replaces that clause; older clauses are never searched. Other corrections stay with the model. If the output reads like a reply, drops line breaks, loses more than one fifth of distinct source words overall or within a sentence, or removes a spoken English/Hebrew script, the prepared transcript is used. Each spoken line goes to the model alone, because the model drops line breaks when it sees them; a rejected line falls back by itself and the others keep their clean-up. `CleanupPrompt.run` and `polish_text` do this, in the same order. A Hebrew prefix split from its word can be rejoined without counting as a lost word. "Skip AI clean-up" bypasses AI rewriting; speech recognition can still change fillers. Dictionary replacements are applied in every path.

   "Polish the text" (`RefineLevel.polished`) swaps in a prompt that may reword (`polishedSystemPrompt`), so the rule above can't apply. Its own check (`isPolishFaithful`, shared cases in `shared/polish-guard-fixtures.json`) accepts changed words but rejects lost sentences, translation, changed numbers and reworded dictionary terms. A rejected polish gets one ordinary clean-up, so a failure costs a second model call rather than the punctuation. The check compares words, so it can't see a changed Hebrew verb form: on the default model a synthetic sentence had its addressee's person changed despite the prompt's rule against it. The history comparison is how a user sees that. Workflows and the Shortcuts action stay at ordinary clean-up, because their words often go on to be matched or sent. A connected Mac recovering a recording finishes it through the main Mac at ordinary clean-up too.
6. **Typing.** The target pastes the text (`PasteService`, ⌘V with the clipboard restored). If it can't, the text stays on the clipboard and an alert says so. In Finder, the original text-field snapshot must still be the directly focused editable AX element in the current Finder process before any paste event; otherwise text stays on the clipboard, avoiding Finder’s text-clipping file action. Unreadable fields in other apps retain the existing best-effort paste. Before pasting, the text is joined to what's already before the caret (`InsertionSeam`): a leading space when needed, and a common first word lowercased when the text before it is mid-sentence. Only the new text changes; fields that expose no text get it as it is.
7. **History.** When history policy allows saving, the Core records the engine’s `heardText` alongside the final inserted text with where it landed, which models ran and how long it took (`recordHistory`). `polishModel` says which model was asked; `cleanupLevel`, `cleanupOutcome` (`CleanupOutcome`) and `cleanupMs` say what was chosen, what really happened and how long it took. A speech server reports these in `X-Polish`, `X-Polish-Level` and `X-Polish-Ms`; one that sends no level ran an ordinary clean-up, so a Polished request counts as a fallback. Home shows this as a tag on each row (`CleanupStamp`), and Settings › Dictation shows one line for the last 50 (`CleanupSummary`). Both are counts of what happened, with no advice, and nothing leaves the user's Macs except by the usual sync between them and Datasets exports. A save error retains the recording and reports a failure to all peers, including peers asking for the outcome after reconnecting; their recovery copies are not deleted as if saving had succeeded.

If anything fails, the Mac you pressed the key on shows a plain-language alert (`DictationAlert`). The recording checkpoint is kept and listed under History & Privacy › Needs your attention, to turn into text later (`RecoveryService`).

An empty recognition result only discards audio that passes the same conservative silence check used by recovery. If an audible chunk returns no words, the whole recording stays recoverable and no partial transcript is pasted. Ordinary pasting has a 20-second response deadline; commands add their configured pauses, text-field waits, Apple Shortcut limits and time for app opening and web requests.

## Speech and clean-up models

- **Whisper through WhisperKit** runs in the app on any Mac (`Services/Speech/LocalSpeechService.swift`). Models download to `~/Library/Application Support/Dictator/SpeechModels`; their ids look like `whisperkit:openai_whisper-large-v3-v20240930_turbo`. Settings › Dictation › Languages you speak (`SetupRouting.languages`) controls language selection. With multiple choices, the allowed language with the highest detector probability is selected; a single choice is used directly. An empty list or detector failure falls back to unrestricted detection. Normally one decoding language is used per recording, even with several languages selected. That metadata does not prove transcript accuracy or every language spoken; mixed-language words can be changed or omitted. Dictionary words are passed as prompt tokens.
- **Apple speech recognition** (macOS 26+) uses `SpeechTranscriber` where it covers the language and `DictationTranscriber` otherwise (the only one with Hebrew). Ids look like `apple:he-IL`; macOS downloads the assets.
- **Clean-up models** run in Ollama on the Mac they're installed on. Dictator never exposes Ollama on the network; other Macs reach it through Dictator's own connection. `RefineLevel` offers `exact`, `medium` and `polished`. `polished` is stored and sent as the retired value `strong`, which older Macs normalize to `medium` and older speech servers treat as ordinary clean-up, so choosing it needs no protocol change. A pre-existing saved `strong` therefore loads as Polished. The retired `light` still normalizes to `medium`; unknown wire values are still rejected. `customSystemPrompt` stays in the mirrored settings format for older Macs; nothing reads it.
- **Downloads** for another Mac go through the Core (`model.pull`, progress in `model.pull.progress`). The models offered, with the memory each needs, are in `shared/model-catalog.json`; any Ollama tag can be typed.
- **The speech server** (`server/`) runs Whisper (MLX) and Gemma through Ollama on one Mac. Its clean-up prompt and faithfulness check are the source for `CleanupPrompt`; `CleanupPromptTests` uses the same cases as `server/tests/test_polish_guard.py`.
- **Speech authentication.** Server startup loads `DICTATION_TOKEN_FILE` (default `~/Library/Application Support/Dictator/speech-server.token`), atomically creating a random 0600 file only if missing. Empty or unreadable files prevent startup. `/transcribe` and `/warm` require a Bearer key compared with `hmac.compare_digest`; a missing or wrong key returns an empty 401 before processing. `/health` remains open and never reveals the key. The app only reads the server-owned local file through `LocalSecret` and never creates or overwrites it. Settings › Advanced › Speech server key saves a pasted remote key atomically in the separate 0600 `speech-server-remote.token`. No migration is needed because pasted keys have not shipped yet. Key selection is a pure function of the request host, this Mac’s interface addresses from `getifaddrs`, and the two keys: loopback or an own interface address uses the local key only; another host uses the remote key, falling back to the local key. In particular, `http://100.101.102.103:7878` uses the local key on the Mac owning that address. The environment override applies only to the server-owned local key. Neither key enters `UserDefaults`, history, logs or the settings mirror. All remote servers, including backups, must accept the same remote key. A key alert for live dictation initiated on another Mac points to Settings › Advanced on the main Mac, naming it when known, and has no local action button; local dictation and direct recovery keep the button.
- **Speech address safety.** The pure `SpeechEndpoint.validated` rule builds on `ServiceEndpoint` without changing its other callers. HTTPS accepts any host; HTTP accepts only loopback, `100.64.0.0/10`, `fd7a:115c:a1e0::/48` and `.ts.net` hosts, using parsed IP bytes for range checks (including IPv4-mapped IPv6). Advanced validates main and backup addresses. Warm-up, recognition, reachability and health inventory requests all enforce the same rule; speech redirects are refused so neither audio nor the key is forwarded. Invalid saved addresses are retained for correction and produce an explained dictation failure rather than sending audio. The source chain still tries backups; if all fail, a key/address problem takes precedence over later outages and travels in the existing encoded `DictationAlert`. Recovery retains the alert and audio and offers the same Advanced action. Older peers can still show its plain message even if they do not recognize the action; the protocol version is unchanged.
- **Server archives are opt-in.** `DICTATION_KEEP_TAKES` defaults to `0`, saving no new audio or transcripts on the server. Above zero, its existing rolling WAV/JSON archive stores audio and text regardless of the app's history setting. Disabling it leaves existing takes alone and adds no cleanup. App recovery checkpoints retain their separate failure-recovery behavior.
- **Deployment order.** Install the updated app on requesting Macs first, then restart the speech server. The updated app keeps working with older servers that ignore the header; older apps cannot authenticate after the server upgrade. Once the server creates its key, same-Mac requests read it automatically. Add that key in Advanced on other requesting Macs, including Macs doing direct recovery.
- **Models unload after an idle period.** The speech server starts with nothing loaded. At key down on any Mac, the Core sends `POST /warm` to the server the dictation will use (`prepareModelsForDictation`), with the refine level that server will get, so the models load while the user speaks. Gemma is left out when the words are typed exactly as spoken or cleaned up elsewhere. A request waits for a load in progress. After five idle minutes (`DICTATION_IDLE_UNLOAD_S`), the server drops Whisper, and Ollama drops the clean-up model through a finite `keep_alive`; the app's own Ollama calls use the same window. The server caps MLX's buffer cache and runs clean-up with a text-only copy of the model (`<model>-text`, without the unused image/audio part). `/health` never loads anything and reports `ok` while the models are unloaded.

## The setup picture (Settings › Your Macs)

Each Edge reports what it has in its capabilities: product name, memory and Tailscale IP (`MachineProfile`), microphone, Ollama models, speech models, and whether Apple speech is available. The Core's `SetupDirectory` keeps every Mac that has ever connected (offline ones stay until removed), matches speech server addresses to Macs by Tailscale IP, checks each server's `/health` every 20 seconds, and sends the result (`SetupSnapshot`) to every Edge in a `setup` message. Each Mac keeps the last one on disk, so it can still draw the page when the Core is off.

That persisted report is inventory, not current connectivity evidence. While a Mac configured to connect to a main Mac is disconnected, Your Macs and General explicitly use the current connection state: other Macs are unavailable through the relay, cached speech-server health is shown as unverified, and sync routes wait. A direct speech server may still work; the UI does not claim it is down. Current local speech and Ollama inventory can still make this Mac's own models available. The presentation preserves the original report, its inventory and timestamps; it changes no routing, stored fields or wire messages. Without explicit connection context, these views fail closed for a connected-Mac role.

## Adding a Mac

While Settings › Your Macs › Add a Mac is open on the main Mac, it accepts join requests for ten minutes and announces itself on the local network (`_dictator-setup._tcp`). The joining Mac lists what it finds, or resolves a typed Tailscale name (only addresses in Tailscale's range are accepted), and sends `pair.request`. The Core answers with a random six-digit code (`pair.code`), shown on both Macs; only the user's OK on the main Mac sends the pairing token (`pair.approved`). The joining Mac saves it and connects with `hello`. One join waits at a time; a copied invitation (`dictator-invite:` plus base64 JSON of name, address and token) is the fallback. An invitation must carry a Tailscale address, and `coreURL(for:)` accepts only such an address or a well-formed `*.ts.net` name. If the pairing token can't be saved, the join fails and the role doesn't change.

Removing a Mac requires confirmation on the main Mac, whether the other Mac is connected or offline. `CoreHost.revokeAccess` first asks `CoreServer` to generate and atomically replace `core-pairing.token` through `LocalSecret` (a 0600 temporary file, flushed before rename). On the server's serial receive queue it swaps the in-memory token, disconnects the removed Mac, then sends `pair.token.rotated` only to the remaining authenticated connections. Hello validation uses that same queue: an old-token hello processed after the swap receives the existing `error` with code `auth`, even if its socket was already open. A failed write leaves the old file and in-memory value in place and disconnects/removes nobody; Settings explains the failure. With no listener, the replacement is still saved for the next listener. The broker disconnect happens before `SetupDirectory.forget`, whose offline guard remains in force. Queued callbacks from a disconnected connection cannot restore its listing or deliver more requests.

Each updated connected Mac saves the replacement for the exact main-Mac address through `PairingCredentialStore`, updates its reconnect credential, then sends `pair.token.saved` with a rotation ID only. The server accepts an acknowledgement only for that connection's pending rotation. Secrets never enter logs, settings mirroring or history. These are optional message types; `EdgeProtocol.version` stays 2. Older peers ignore the rotation and remain connected until their link drops, then need to join again. A Mac that disconnects during delivery may also need to join again; there is no rollback to a revoked token.

An offline Mac cannot receive the replacement. Its next hello is refused, including if it changes its claimed Mac identity. `CoreConnection` turns `auth` into a plain explanation pointing to Settings › Your Macs › Add a Mac on the main Mac. It stops reconnecting, and the coordinator's liveness watchdog does not rebuild that stopped connection. Saving a replacement unsuccessfully also stops the connection with an explanation and sends no acknowledgement. Your Macs offers the existing Join Another Mac’s Setup sheet in this state; joining again creates a new connection using the saved new credential. No local history is deleted. The removal confirmation names the other offline Macs that must join again. Any configured speech server has a separate key that a removed Mac may still hold, including a server on the main Mac or loopback. Removing a Mac does not change that key; see [server/README.md](../server/README.md) for changing it.

## History, dictionary and settings

- Saving history is on by default for a new install.
- Home retains its history feed while switching tabs. It loads the newest 100 entries first and reads another page only with **Load older entries**. Only loaded pages are laid out, using an eager stack to avoid the lazy stack's accessibility-scroll trap after a page append. Local reads run on background SwiftData contexts. Filters query the whole local store using metadata, so older destinations and typed entries remain accessible without loading every transcript. A history revision refreshes the feed; export and Clean Up read the whole store only when requested. Replication keeps its existing byte-budgeted pages and exclusive `(timestamp, id)` cursors.
- Every Mac reads and writes only its own SwiftData store (`~/Library/Application Support/Dictator/Dictator.store`). `HistorySyncEngine` replicates with the Core: new rows start as pending and are uploaded by id, missing live rows are pulled down, and deletes and dictionary edits use the persisted outbox (`SyncOutboxItem`).
- Explicit history deletes save content-free `HistoryDeletion` records (ID and deletion time) in the same local transaction as row removal and, on a connected Mac, the outbox item. These records stay indefinitely for offline peers. On attach or a full sync, each connected Mac sends local deletion IDs missing from the main Mac's proof in bounded, idempotent delete requests, then refreshes the manifest. This includes deletes made while on its own and repairs proof lost by an older main-store restore; the outbox is not the only source of intent. Delayed uploads, old pulls and repeated imports cannot recreate deleted IDs. Import previews count previously deleted IDs separately and keep them excluded.
- The main Mac serves deletion proof through the existing byte-budgeted manifest's optional `deletedAt` field; a marker's `timestamp` is its deletion time. Deletion pages use a unique indexed key encoding the exact date bits and UUID, so a large one-call deletion does not rescan its whole timestamp group per page. Updated peers retain the proof and remove matching rows, including pending ones, before uploads. History notifications and local pushes walk the complete metadata manifest: future-dated or imported rows must not hide a later deletion marker. Only unknown live rows and rows whose optional `hasEditedText` marker is newly present need their text fetched. The first observed edited stage is immutable; replication merges that stage into an existing row without changing text, timestamp or aggregate stats. This adds a metadata scan per history pass.
- Missing rows without deletion proof still use the original wipe guard: the engine refuses to remove more than 50 synced rows when they also exceed 25% of the remaining synced set. Explicit markers authorize only their own IDs. Old peers ignore the optional field and cannot apply these deletions, so every Mac must be updated before relying on cross-Mac deletion. Deletes made before this metadata existed have no proof and retain the legacy guard. The protocol version stays unchanged.
- Shared settings are mirrored between the Core and every Edge (`CoreSettingsMirror`, `CoreSettingsDTO`): whether history is saved, clean-up on or off, the typed-history policy (`surfacePolicyJSON`), which Mac records (`micOwnerEdgeID`, empty for Automatic), which Mac does the other jobs (`setupRoutingJSON`), the commands and lists (`voiceLaunchJSON`), vocabulary pack selection (`vocabularyPacksAutomatic`, `vocabularyPacksOn`, `vocabularyPacksOff`), correction learning (`learnFromCorrections`, on by default). The recording picker is available in every role, including on connected Macs whose main Mac is distant or screenless. Its optional wire field preserves the local choice when absent and explicitly returns to Automatic when empty; validated changes update the main Mac’s broker without changing its role or connection. Changing one on any Mac changes it everywhere. The hotkey mode is set by the Core and pushed in `config`.
- Sync events are logged as `sync:` lines in `~/Library/Logs/Dictator/hotkey.log`.

**Dictionary matching.** Recognition hints reach the speech server, WhisperKit and Apple, including Commands and Teach. They are ordered by owner name, starred words, then frequency with recency breaking ties, Commands names, nearby words and packs; in Commands mode its names come first. Nearby text is currently empty; Dictator does not read around the cursor for hints. `vocabularyHintInput` fills fields from mirrored selection, cached installed apps and configured languages, using the target Mac’s app identity from the session snapshot. Pointer-only focus reports preserve the last app report for that same Mac. Sentence frames and the 200-token Whisper budget live in `shared/vocabulary-hints.json`; each Whisper engine fits whole terms with its own tokenizer, including the frame after language choice. Apple receives the first 100 ordered terms. The server splits hinted long audio at quiet points into windows under 30 seconds, supplying the same prompt to each; hintless decoding is unchanged. WhisperKit's VAD chunking copies prompt options to every chunk, with prefill enabled for hinted automatic-language decoding too. Take diagnostics retain the fitted term count, never the hint words. Clients requesting JSON receive `text` and `raw` (before dictionary/clean-up); older clients retain plain text.

Vocabulary entries preserve recognized spelling except single ordinary Title case words such as Slack, Notion and Whisper, which are recognition hints only. Mixed-case, all-caps and multi-word vocabulary entries, and explicit replacements, still rewrite text when clean-up is off. Matching ignores case and accepts spaces, hyphens or comma-space between pattern words; runs of single letters also accept dots, hyphens or no separator. Patterns with at least three letters retain a trailing s, es, 's or ’s. Hebrew patterns accept one attached prefix letter from `VoiceLaunchText.hebrewPrefixes`, preserving it. Letters, numbers, combining marks and underscores otherwise prevent matches inside larger words. Longer phrases win at the same position; explicit replacements beat vocabulary at the same span. Matches are chosen from the original transcript, so one rule's output is never input to another. AI clean-up receives corrected text and restores target spellings afterwards without replaying source rules. Both matchers read `shared/dictionary-matching-fixtures.json` in tests. A consistently misheard name still needs an explicit replacement.

**Vocabulary packs.** `shared/vocabulary-packs/<id>.json` supplies English terms, summaries, bundle IDs and an optional always-on flag; `project.yml` bundles the folder and `VocabularyPackCatalog` loads its top-level files. Common terms are always included unless explicitly off. Automatic selection adds packs associated with locally installed apps or the reported destination app (which can be on another Mac); manual On adds packs and Off beats every source. Only the person's configured languages apply (regional codes share their base language). Active packs are ordered by destination app, manually enabled fields, installed-app fields, then always-on packs. Terms are merged round robin in each pack’s authored order, with destination packs taking two turns per round, so fields share the 200-token budget. Terms are de-duplicated without changing the first spelling; personal words remain ahead of packs. `InstalledApps.bundleIDs()` performs cached, background LaunchServices queries for catalog bundle IDs, without scanning folders or launching apps. Installed-app results remain local; only the three optional pack policy fields travel through the settings mirror. Medicine, law, finance and marketing/sales currently use manual selection because they lack reliable, specific native-app associations.

Each pack's `metadata/<id>.json` owns the display text, language, app list and always-on flag. Original authored candidates live in `candidates/<id>.txt` (120–160 terms). Shipped starter packs contain the first 45 candidates and are not measured. `scripts/vocabulary-packs/evaluate.py --model-repo <local-directory-or-cached-repo-id>` explicitly evaluates four installed English macOS `say` voices with matched unaided/hinted offline MLX Whisper decodes. It uses `shared/vocabulary-hints.json`'s English frame when present, otherwise the contract's sentence frame. It ranks unaided misses first, then recovered terms, fits the complete prompt to 200 tokens using that model's tokenizer (including Whisper's leading space), and replaces the pack JSON using the same metadata. Audio is temporary outside the checkout; optional score reports must also stay outside it. It never downloads models or voices or contacts the speech server. `--dry-run` tests three terms per pack with stub audio, decoding and token counts, writes only outside the checkout, and does not measure recognition. Unit tests use synthetic text and fixtures only.

**Dictionary screen.** Fields are equal-height toggle chips that wrap to the available width in both Dictionary and welcome; a dot, tooltip and one legend identify automatic app selections. Always-on fields stay out of that row. One words list combines spelling and heard-as rules; heard-as spellings are shown once ignoring case, and forgotten rows never appear. Dictionary pages sort lexically by `(pattern, id)`. New peers send optional `afterID` with `afterPattern`, preserving every equal-pattern identity across count and byte-budget boundaries; omitting the id retains the older exclusive pattern-only cursor. Search includes heard-as spellings. The same Add/Edit sheet starts with Word and reveals optional heard-as fields; Return saves. More starts collapsed and remembers its state per window through `SceneStorage`; it holds phrase matching, ordered recognition words and space used, learning and automatic-field settings, and text import/export. Phrase matching calls `CleanupPrompt.applyReplacements` with the same filtering as dictation (forgotten rows and learned hint-only rows excluded). Recognition preview builds from the page’s loaded entries using the same explicit-input `VocabularyHint.vocabularyHintInput(entries:...)` builder and `orderedTerms` as dictation, so stars and reloads apply without reading a second repository. Words that do not fit appear as a count with a collapsed disclosure for the list. Preview uses an already loaded local tokenizer when available, otherwise a labeled conservative estimate; it never loads assets or calls a speech service. Preview is for ordinary dictation without a destination app; the actual engine, language and destination can change what fits. Import can replace conflicting heard-as spellings in place. Export uses the existing plain word / `heard -> spelling` format, with a version comment and JSON-escaped `@word` lines for otherwise ambiguous words; the parser only recognizes escapes under that version header and continues reading old imports. Export preserves spellings and rules, not star/usage metadata. The welcome flow adds an optional fields step with equal Skip and Use actions. It loads both explicit On and Off choices; Use saves both, while Skip changes neither. Voice history rows offer Fix a word with contiguous word chips and plain confirmation; typed rows do not. The sheet displays the latest edited stage when present and sends optional `selection` containing its full text snapshot and offsets counted in Swift Characters (extended grapheme clusters). The main Mac checks the snapshot and selected text against the current row, refuses stale selections before any learning, and replaces only that occurrence. Legacy requests without a selection can teach the dictionary but cannot change the history sentence.

**Learning from corrections.** `Services/Dictionary/CorrectionLearner.swift` is a pure Unicode diff and validation policy with an injected spell checker. It accepts at most three changed spans of one-to-one word substitutions, and declines unrelated rewrites, insertions/deletions, short/long terms, markup, code, paths, addresses, numbers and opaque identifiers. The production adapter checks ordinary words through `NSSpellChecker` in the person's configured languages (system preferred spelling languages when none are configured). Internal brand capitalization can pass that ordinary-word filter. A new accepted spelling is a hint-only vocabulary row (`origin: "learned"`); it is excluded from the replacement/clean-up dictionary. Recognition hints read dictionary rows independently, so that spelling can aid all engines without creating an automatic rewrite. A matching heard-as rule needs two distinct observed corrections; the explicit History action `DictatorViewModel.learnCorrection(heard:corrected:entryID:selection:)` uses the same filters and can add that rule immediately. The main Mac owns learning. The persistent confirmation ledger in defaults contains salted hashes, bounded counts and dates, never words; it retains at most 64 pending pairs for 30 days and 128 recent observation hashes. Additions are limited to five dictionary rows per day. Diagnostics log only candidate/addition counts.

On the Mac that inserted the dictation, `EditWatcher` performs one post-insertion AX read and one final read when focus leaves the field, the app changes, another dictation begins, or 60 seconds elapse. There are no text-change/keystroke observers or reads while typing between those events. It retains only the inserted span, short neighbour anchors and an opaque field handle in memory, then discards them. The final AX string-range read is bounded to the insertion window and its anchors, adjusted by the field's length change. Length only bounds the read: it never proves ownership. The insertion must be uniquely located, its anchors must still bracket a single span, and every changed word must be a plausible one-to-one substitution. An equally good alignment that adds characters at either outer boundary also fails closed. Extensions at either end, extra or missing words (including when the right anchor is empty), changed neighbours and ambiguous anchors abandon the entire observation: nothing is saved, sent or learned.

Correction learning has its own switch (`learnFromCorrections`, on by default), independent of history saving. Secure input/fields, unreadable terminal fields, Pause, and places explicitly excluded for either voice or typed capture are skipped before any field read; the gate is checked again before the final read and delivery. Default-off typed history is not an explicit exclusion. When typed capture is allowed for that place through `AppSettings.captureDecision`, an owned corrected sentence may become the existing dictation row's first `editedText`. Otherwise the inserting Mac filters it into individual word pairs using the ordinary-word/unsafe-text checks before delivery; no corrected sentence is sent or kept. Pairs are never logged, and the confirmation ledger holds only hashes. Turning history off prevents every history-stage write but still permits filtered pairs to teach the dictionary. Deleting a history row cannot recreate it; learning does not require a history row.

Insertion does not await learning. A connected Mac sends ephemeral observations in the optional `RepoRequest.correction` request, with optional `pairsOnly` and destination `context` fields; older main Macs ignore unknown fields/requests. There is no outbox, offline typed capture or queued transcript. The main Mac rechecks correction consent and typed-history policy; the history repository independently enforces typed consent and first-edit-only semantics on automatic `saveEditedText`. Deliberate History fixes use separate `saveManualEdit`, which checks the global history switch and expected current text, allows later fixes, and never recreates a missing row. Each manual fix advances a default-zero `editedTextRevision`, optional in DTOs and manifests; sync fetches newer revisions even when both Macs already hold an edited stage, and an older upload cannot overwrite one. The original final dictation stays in `text`; fixes replace `editedText`. Correction responses retain `kind: "ok"` with optional `correctionOutcome` (history saved, spelling learned, and optional learning failure). Main-Mac save errors return repository errors, and the requesting Mac shows the actual outcome. A successful history fix followed by failed dictionary learning is reported as partial success. Older main Macs returning bare `ok` are described as receipt without a confirmed save. History stages share text's replication limits and byte-budget truncation. `DurableTranscriber` aggregates raw and final chunks in order for takes over 110 seconds, using each chunk's returned text when its raw stage is absent, then publishes the complete raw stage once for history. Recovery uses the same stage-aware chunker, and Shortcuts Dictate saves the listened words before clean-up. `heardText` uses the transcription result's optional `rawText`, falling back to its returned text on older engines/servers.

Dictionary rows also carry optional/defaulted star, usage, origin and forgotten fields. Deleting a learned row retains an `isForgotten` tombstone, hidden from the screen, hints, replacements, usage and future learning. New peers request dictionary pages with optional `includeForgotten: true`. Requests without that field (or with false) receive active rows only, filtered before pagination, so older peers discard previously mirrored forgotten rows instead of using them. New peers retain local tombstones even if an older main Mac omits them. Undo clears `isForgotten` on the same learned identity, preserving metadata; manually adding a matching forgotten pattern of the same row type also reuses that identity and sends its cleared tombstone through the normal outbox. An omitted forgotten field from an old peer cannot clear a tombstone. Restored words participate in learning normally even when a different heard-as rule for that spelling remains forgotten; the forgotten rule still blocks recreating its own source pattern. Manual/imported rows keep their existing delete/undo behavior. Patterns remain nonunique across independently created vocabulary and rule rows, hence the composite dictionary cursor. Only the main/standalone Mac counts complete dictionary terms in finished dictations' final text. `DictionaryUsageBatcher` coalesces counters in memory for 60 seconds and commits once, plus a synchronous quit flush. Usage writes are quiet: no `onChange`, revision notification, broadcast or outbox entry. Connected Macs pick up the counts on the next real dictionary change. Repository notifications distinguish local edits from mirror-applied changes: both refresh the UI, but a mirror-applied change never schedules a history push pass. All new nonoptional SwiftData properties have declaration defaults, and the stages are optional, for unversioned lightweight migration. Optional DTO fields use Codable's synthesized `decodeIfPresent`; an omitted old-peer field never resets newer metadata.

## Commands

A spoken **pattern** fills named **slots**, and the slots feed a linear chain of **steps**. Everything is deterministic: exact matching against fixed words and user lists, no model judgment.

- **Data** (`VoiceLaunch.swift`). `VoiceLaunchConfig` (`version: 2`, `lists`, and `commands`, stored as `shortcuts`) is one shared setting (`voiceLaunchJSON`, mirrored like the others through `CoreSettingsDTO`/`CoreSettingsPatch`, validated in `RepoServer` and `LocalCoreSettingsRepository` by `VoiceLaunchConfig.validate`). Caps: 100 commands, 20 lists, 500 entries per list, 20 steps per command. A list (`VoiceList`) has fields and entries; an entry has the names you say (first is the display name, the rest aliases) and a value per field. A command has a readable pattern (`Email {person:People} [subject {subject} body] {body}`: fixed words, `{name:List}` list slots, `{name}` text slots, one level of `[optional]` groups), an optional `cleanUpSlot`, and steps. Step types: `openLink`, `openApp`, `waitForTextField`, `typeText`, `pressKey`, `runInTerminal`, `confirm`, `runAppleShortcut`, `webhook`, `appendToFile`, `runWorkspace`. Validation gives plain-words reasons: the pattern starts with a fixed word, a text slot is last or followed by a fixed word (its end marker), slot names are unique, lists exist, references (`{slot}`, `{slot.field}`) exist, link schemes are in `allowed_link_schemes`, and acting steps (Return or ⌘Return, Apple Shortcut, web request) need an earlier `confirm`.
- **Gesture.** `HotkeyService` watches two `KeyCombo`s on the same tap, held in `HotkeyTriggers`: the dictation keys and the Commands keys. Each is per-Mac, stored in `dictationKeys` and `commandKeys`, and defaults to Right ⌥ and Right ⌥ + Right Shift; `hotkeyKeyCode` keeps the first dictation key. Any regular key in a combo is held back from the app in front. `KeyComboRules` refuses keys that could not work. The Commands keys being down at any point while the press lasts, or when a tap starts, sends `shortcut.mode` (`EdgeMessage.voiceCommandMode`, a new message type, no version bump); the broker marks the session and re-broadcasts it (`SessionStateUpdate.voiceCommandMode`, optional), so the Mac showing the indicator, which may not be the one with the keyboard, changes the badge and adds a "Commands" label. Plain Right ⌥ never does.
- **Matching happens on the Core**, on the raw transcript before clean-up (`CoreHost` calls `DictatorViewModel.resolveVoiceCommand` for Commands sessions only). `VoiceLaunchEngine.match` tokenizes Unicode-aware (Hebrew works), compares on lowercased, punctuation-stripped words, and keeps each slot's original text. A small backtracking matcher takes exact fixed words, the longest list name or alias, marker-ended text slots up to the first marker (at least one word), a final text slot that takes the rest (may be empty), and optional groups tried present then absent. The whole transcript must be consumed. The winner has the most words consumed by fixed words and list slots; a tie between different commands means no match. `VoiceLaunchEngine.plan(for:in:)` is the pure function (match, slot values, rendered steps, or why nothing matched); the Core and the tests use it. In Commands mode the speech step skips clean-up, and its fixed words and list names lead the recognition hints on every speech route.
- **Clean-up.** Only the command's `cleanUpSlot` goes through clean-up (when it is on); dictionary replacements apply to every text slot; list values never go through clean-up. If nothing matches in Commands mode, all the words are kept on the clipboard with a notice; nothing is typed. Plain dictation still uses the normal insertion path.
- **Rendering.** `VoiceLaunchEngine.render` encodes each value for where it is used: percent-encoded query components in links (trailing punctuation dropped from text slots that weren't cleaned up), raw in typed text, one shell-quoted word each in the Terminal script (`ShellQuote`), JSON for webhooks. Unknown or missing optional slots render empty.
- **Delivery happens on the target Mac.** The Core sends the resolved `VoiceLaunchPlan` as `insert.launch` (`CoreMessage.launchInsert`, a new optional message, no version bump; older Macs ignore it) instead of `insert`; the target answers with the usual `insert.result`. No-match notices and older Cores still use the first version's `insert.shortcut`. `VoiceLaunchExecutor` runs the steps in order and stops at the first failure with an alert naming the step ("Couldn't find a place to type in WhatsApp"); later steps never run. It refuses a plan that has a step this build can't run before running any. The steps: `openLink` (scheme checked again on the target), `openApp`, `waitForTextField` (expected app frontmost and an editable focused element, default 8 s), `typeText` (`PasteService`), `runInTerminal` (private self-deleting `.command` script). The executor also supports `confirm`, `pressKey`, `runAppleShortcut`, `webhook` and `appendToFile`, described below. If a step fails the main words stay on the clipboard. The target returns the encoded alert as a failed insertion outcome; the existing initiator-only idle handler shows it on the dictating Mac and retains the recovery recording. No-match notices without an interactive near-miss picker follow the same route, preserving tie details and the Commands action.
- **Apps and workspaces by name.** The “Open an app” card (`open-app`, `Open {app}`, example “Open Safari”) has one `openApp` step whose `text` is `{app}`; existing `bundleId` steps take precedence and keep their behavior. The “Workspaces” card (`open-workspace`, `Workspace {workspace}`, example “Workspace writing”) has one `runWorkspace` step whose `text` is `{workspace}`. Neither has clean-up or a confirm pause. Both name fields render on the main Mac through `VoiceStepRenderer`, including deferred answers, but resolve on the target Mac. `VoiceNameResolver` folds case and diacritics, removes spaces and punctuation, a `.app` suffix and a trailing parenthesized label. It requires one exact normalized match, never a prefix, fuzzy match or model guess. Empty names and multiple matches fail; ambiguous alerts list the matching names. App enumeration (`VoiceInstalledApps`) runs off the main thread, reading /Applications, /System/Applications, /System/Applications/Utilities and ~/Applications, their immediate child folders, and no app bundle contents. Distinct installations with equal names remain ambiguous; duplicate paths are removed. A cached background snapshot adds this Mac’s app names after command/list hint words within the existing 400-item limit; recognition uses the previous snapshot and refreshes it without blocking key-down.
- **A routine's own voice command.** `VoiceStep.workspaceId` is optional, included in coding keys and preserved through normal/deferred rendering and `insert.launch`. On the target Mac it takes precedence over name lookup, including after a rename; a missing ID fails with the spoken phrase and no suggested replacement. Without an ID, the Workspace card and existing text/slot name lookup are unchanged. ID-based rendering carries the raw spoken phrase in `text` for a failure; linked commands without text slots retain those words as `mainText` for the clipboard. `VoiceWorkspaceLink` in `VoiceLaunchEditing.swift` provides pure find/add/phrase-change/remove/rename operations. Creation makes an enabled command named after the routine, with literal words, one ID-linked workspace action, no clean-up and no confirmation pause. `VoiceBuildProblems.workspacePhrase` rejects typed curly/square brackets, uses the existing parser and matcher (including off commands, aliases and filled-in sentences) to name conflicts, and applies the normal save limits. All writes use `AppSettings.updateVoiceLaunch` and the existing settings mirror. Workspaces offers the command row on every routine, independent of its actions and this Mac's execution permissions: add/edit in a one-field sheet with this Mac's actual keys, remove without confirmation, enable an off command, and show the first link plus a count of others. Phrase edits retain the command's other settings/actions and enabled state. Teach remains available in the Commands editor. The Run a workspace editor offers saved routines by ID or “The name I say”; summaries resolve the current name from saved routines.
- **Workspace execution and compatibility.** `VoiceLaunchServices` injects names, app opening and awaitable workspace execution for synthetic tests. `WorkspaceLaunchController.runAwaiting` shares `performRun`, waits for local changes and normal multi-Mac fan-out, and throws for a busy controller or failed run. Workspace run replies and fleet reports carry an optional `failure` alongside the existing summary, so remote failures and missing replies reach the voice failure path; older peers omit it and retain their summary behavior. Later steps run only after it finishes successfully, in their original order. The insertion watchdog adds a 60-second budget per workspace step, covering capture, cooperative changes and the fleet round trip. Failures use the existing executor `Failure`/`insert.result` path, keep the words on the clipboard and show a plain alert on the dictating Mac. **Kind decoding remains strict:** an older build that reads a voice config containing `runWorkspace` cannot decode that config and reads Commands as empty. Update all Macs before enabling this step. Validation is not weakened and `EdgeProtocol.version` is unchanged.
- **Duplicates and ties.** Catalog/card adds reuse and enable a command with the same parsed `matchingKey` (including patterns with different slot names), rather than adding another. The editor reports equal patterns through `VoiceBuildProblems`. Runtime ties name the matching commands, ask the user to turn one off or change what they say, retain the words on the clipboard, and offer an action opening Commands.
- **Timing.** Each step logs `voicelaunch: step 2/3 openLink ok 12ms` to `~/Library/Logs/Dictator/hotkey.log`, plus `voicelaunch: total 431ms (from key release) 3 steps`.
- **Ready-made.** `shared/shortcut-catalog.json` (version 5; `groups` lists the headings of the simple view in order; each template may carry a `card` with a plain title, an example sentence, the one question it asks, its `group`, a one-line `does` (a variant's `does` is shown while that variant is in use), and icon hints: `apps` (bundle identifiers) and `site` (a host)) holds `allowed_link_schemes`, the empty lists People (phone, email) and Projects (folder), and templates made of the same parts. It includes "WhatsApp and send" (`WhatsApp and send {person:People} {message}`: open the link, wait for WhatsApp's text box (`net.whatsapp.WhatsApp`), ask, press Return). A template can set `"hidden": true` to stay out of the tab. The Commands tab has two layers. The simple layer (`VoiceLaunchView`) shows cards (from `VoiceCommandCatalog.runnable`; `VoiceCardsSection`, logic in `VoiceCards`: a switch enables or disables the catalog command; WhatsApp asks check-first or send-right-away and keeps exactly one of the two templates, the send one taking the plain pattern; Claude Code asks for project folders and creates Projects entries), a card's icon (`VoiceIconSource`: the hinted apps, the hinted site, then what its first action reaches — the app it opens, Terminal, Shortcuts, the app for a link scheme, or the link's host — falling back to a symbol for the action or the title's first letter; drawn by `VoiceIconView`; website icons come from `SiteIconStore`, which asks the site for `apple-touch-icon.png` then `favicon.ico`, sends only the host, caches in Caches/SiteIcons and never fetches under tests), tabs (`VoiceLaunchTab`: Things to say, People, and Apple Shortcuts once that card is added), an "On now" strip, compact cards that open one at a time, a "How to say it" legend that folds once anything is on (`VoiceHowToSay`), People (`VoicePeopleSection`, `VoicePeople`, the system `CNContactPicker`, and Check name, `VoiceCheckName` over the same `VoiceTeachSession` with two takes and auto-saved non-conflicting spellings), and "Build your own…" at the top. Every word shown is drawn by role through one view, `SpokenPhraseView` (`PhraseChip`: a solid key for the start word, an outlined pill with a symbol for a person, project or Shortcut, italics for your words; captions optional and off on the cards), fed by `SpokenPhrase` (start word / who, project, shortcut or which / your words, from a pattern plus an example sentence, a plan, or a near miss); it is used on cards, the near-miss notice, Check name, Try it and the progress notice. The advanced layer (`VoiceAdvancedView`) holds your commands (`VoiceCommandEditor`: plain-words validation, a step list with add/move/remove/configure), your lists (`VoiceListEditor`, with full Teach), and a "Try it" box (`VoiceTryItResult`, which calls `plan(for:in:)` and runs nothing). The step menu is `VoiceStep.Kind.addable()`, driven by `VoiceLaunchExecutor.supportedKinds` (now every step type). Adding a step that acts for real (`VoiceStep.isActing`) with no "Ask before continuing" earlier inserts one with a default summary (`[VoiceStep].addStep`, `VoiceStep.defaultConfirmSummary`). The logic lives in `VoiceLaunchEditing.swift` so it is testable. On the target Mac `VoiceLaunchExecutor.run` reports each step to a `VoiceLaunchProgress` (started, done, failed, cancelled, and a per-second countdown), shown by `VoiceLaunchProgressController` in the dictation alert's style.
- **Apple Shortcuts bridge** (`VoiceShortcutBridge.swift`, `VoiceLaunchActing.swift`, `VoiceAppleShortcutFields.swift`). `runAppleShortcut` runs `/usr/bin/shortcuts run <identifier or name> --input-path <file> --output-path <file> --output-type public.plain-text` as an argument array (never a shell), with a per-action time limit (10, 30, 60 or 120 s, default 30; `timeoutSeconds`). The input and answer files live in a private 0700 folder (files 0600) that is removed after the run. *Values in:* a new action sends everything said as `input.json` (`{shortcut, said, values, mac}`; a list value is an object of its name and details; the cleaned slot is the cleaned text; `said` is the raw transcript; Unicode is kept). `inputMode` absent means the older plain-text `input.txt` from the `text` field, so existing actions keep working (nothing is migrated in the stored data). *Values out:* the answer file (up to 64 KB, longer is cut and noted in the log; empty is fine) becomes a value named by the action (`VoiceStep.answerKey`, shown as "answer from Remind"); if it parses as a JSON object its keys are details (the action's `answerDetails` list them for the bubbles). *Deferred rendering:* `VoiceStepRenderer` holds the one set of encoders (percent-encoded in links, raw in text, raw folder and argument for the terminal, JSON for the input file). The Core renders every step with it except a step that uses an answer or builds the JSON input (`needsDeferral`); that step travels with `VoiceStep.deferred` (its templates, the known values, the clean-up slot and the raw words) and its own text fields left empty, so an older Mac (no new message, no version bump) finds nothing to run instead of half a template. The target Mac renders it just before the step runs, with the answers so far and its own name. Validation (`VoiceLaunchConfig.validate` and `VoiceBuildProblems`) allows an answer only in an action after the one that gives it. "Type the answer" is a `typeText` whose text is the answer; the Shortcut's "Type its answer where my cursor is" toggle adds or removes it right after the Shortcut. *Picker:* `shortcuts list --show-identifiers` (run on the Mac showing the editor; `VoiceShortcutList` parses `Name (ID)`), Refresh, Open in Shortcuts (`shortcuts view <name>`), New Shortcut (opens the Shortcuts app); the name and identifier are stored, the identifier is run when present. *Cancel pause:* a Shortcut marked "Doesn't send or change anything" (`readOnly`) is not an acting step, so it needs no pause before it. *Failures* are plain (didn't finish in time, this Mac doesn't have the Shortcut, Shortcuts isn't allowed, stopped with an error); the raw error text (truncated to 500 characters) goes only to `hotkey.log`. Shortcuts doesn't report its own start-up time, so only the step's total is logged.
- **"Run a Shortcut" and "Your Shortcuts"** (`VoiceYourShortcuts` in `VoiceLaunchCards.swift`, `VoiceYourShortcutsSection`). "Your Shortcuts" is an ordinary list (field `identifier`) inside the mirrored Commands setting, so the matcher (longest name wins), Whisper hints, Teach, Check name and "Did you mean" treat it like People and need no special code. It is machine-derived: only the main Mac (or a standalone Mac) fills it, from `shortcuts list --show-identifiers`, at launch (only when a command uses the list), when the Commands page shows it, and from its Refresh button (`VoiceLaunchActing.fetchYourShortcuts` / `refreshYourShortcuts`; a Mac connected to a main Mac never runs it). `VoiceYourShortcuts.merge` replaces names and identifiers on each refresh but keeps the ways of saying a name that the user added (matched by identifier, else by name) so they persist and sync with the setting; a Shortcut that is gone takes its ways with it; two Shortcuts with the same name (ignoring case and spacing) are one entry, the first; the list is capped at 500. A failed refresh leaves the last list. The Build your own list screen shows it without Edit or remove. The catalog card `run-shortcut` (pattern `Shortcut {which:Your Shortcuts} {words}`, off by default) has a `confirm` step (3 s) then a `runAppleShortcut` whose `shortcutName` and `shortcutId` are references (`{which}`, `{which.identifier}`, `VoiceStep.isTemplate`) that the Core fills in `VoiceLaunchEngine.render` (`VoiceStepRenderer.resolvingTarget`) before the step is deferred, so the target Mac runs the matched Shortcut by identifier with everything said as JSON, and its answer is not typed. Its question when turned on is the cancel pause (default) or "right away": the variant `run-shortcut-now` has no `confirm` and is marked `readOnly` (the existing way to skip the pause), and `VoiceCards.setShortcutMode` keeps exactly one of the two with the same pattern and the user's other ways of starting it. A name that starts with a dash is never passed to `shortcuts`. If the running Mac lacks the Shortcut, the phase-1 plain failure applies.
- **Dictator inside Shortcuts (App Intents).** The standard locally signed build does not advertise these actions: `isDiscoverable` is false and the provider is empty unless `DICTATOR_ENABLE_APP_INTENTS` is explicitly compiled in. Settings explains that availability. Native macOS 27 testing rejected the fixed self-signed certificate at `linkd`’s validated-bundle/Team-ID boundary before `perform()`; a genuine team signature and separate native verification are prerequisites for an enabled deployment. Existing Commands → Apple Shortcuts steps are independent. `Services/Shortcuts/DictatorIntents.swift` (the only file that imports AppIntents) exposes three actions, an `AppEntity` and an `AppShortcutsProvider` (phrases include the app name); they run in the Dictator app itself (no extension, `openAppWhenRun` false), so they use this Mac's own speech path and settings, and Xcode's metadata extraction puts `Contents/Resources/Metadata.appintents` in the bundle with no `project.yml` change (macOS 14 target; nothing newer is used). The work is in `ShortcutsBridge` (`ShortcutsBridge.swift`), which talks to the app through `ShortcutsBridgeServices` (set by `DictatorViewModel`, mocked in `ShortcutsIntentsTests`); an action run before the app has set it up, or without a way to reach the speech path, throws a `ShortcutsBridgeError` whose plain message the Shortcuts app shows. **Dictate** (parameter "Clean up my words", default on) reuses Teach's transcribe-only path: a one-take `VoiceTeachSession` on `EdgeRuntime`'s recorder with the same silence endpointer (2 s of quiet, its countdown) but a 2-minute limit (`VoiceTeachEndpointer.maxSeconds`), driving the dictating badge through `onPhase`/`onTick`; the recording goes to the main Mac's speech path (`teachTranscribe`, over `transcribeRequest` from a connected Mac), then `finishTextForShortcuts` applies the dictionary and, when the toggle is on and the clean-up level isn't Exact, the chosen clean-up model. On a connected Mac that second step is a new optional message pair `textCleanupRequest`/`textCleanupResult` (`CoreHost.cleanUpText`, `CoreConnection.cleanUpText`; an older main Mac ignores it and the action fails with "didn't answer in time"; protocol version unchanged). Nothing is pasted. History is written on this Mac through the normal repository (so `captureDecision` applies) with `source: "shortcuts"` and a new `CaptureSource.shortcuts` (`attribution.captureSource`, shown as "Dictation (from Shortcuts)"); both fields already existed as optional strings, so the store and sync need no migration and an older Mac shows an unknown capture source as a plain dictation. **Run a Voice launch shortcut** takes a `VoiceCommandEntity` (id, card title, opening words; enabled commands only, `EntityStringQuery`) and optional "words". The sentence is the command's trigger words plus the words; `VoiceLaunchEngine.plan` runs over a copy of the config holding only that command (so no other command can win), and `VoiceLaunchExecutor.run` executes the plan on this Mac, cancel pause included (`answered:` reports each Shortcut answer). It returns the last non-empty answer, else the plan's main text; a cancel or failure throws with the alert's words. The given words are used as typed: no clean-up and no dictionary, since they are text, not speech. **Clean up text** requires a chosen clean-up model (`cleanupTarget`), then runs the same dictionary replacements and `cleanUp` as dictation, on the main Mac; a model that errors leaves the words as they were, as in dictation. Its description says it uses an AI model.
- **Acting steps** (`VoiceLaunchActing.swift`, run by `VoiceLaunchExecutor`). Everything outside the process is injected through `VoiceLaunchServices` so tests use mocks. `confirm` shows the rendered summary in the progress notice with "Sending in N s. Esc to cancel." (`VoiceLaunchCountdown`, default 3 s). Esc comes from the existing hotkey tap (`VoiceLaunchEscapeWatch.fire()` in `HotkeyService.handleEvent`, plus a local monitor for Dictator's own windows), so it needs no new permission. Cancelling stops the chain, puts the plan's main text on the clipboard and shows a plain notice (`Result.cancelled`, no error sound). `pressKey` (return, cmdReturn, tab, escape) posts a tagged CGEvent to the frontmost app and refuses when the app the chain opened isn't in front. `runAppleShortcut` is described under the Apple Shortcuts bridge above. `webhook` POSTs the JSON body (`VoiceLaunchEngine.webhookBody`) to an http or https address with a 10 s timeout and no custom headers; anything but 2xx is a failure. `appendToFile` adds `yyyy-MM-dd HH:mm:ss | text` to a user-chosen file (created 0600 if missing; failure if its folder is missing). A step's failure or a cancel means later steps never run. `appendToFile` refuses hidden files and folders, Library and system paths, on the resolved path, in validation and again at run time. Spoken words given to a terminal command stay one argument and never start with a dash, so they can't become a flag. A confirmation pause is bounded again on the Mac that runs it, because `insert.launch` skips validation there.
- **Aliases (Teach and the one-click fix).** The speech recognizer mishears names ("Noam" becomes "norm"), so the fix is data, never fuzzy matching at run time. A list entry's extra names are its aliases; a command has `triggerAliases`, other spellings of its leading fixed words (the trigger). `bestMatch` accepts the real trigger or any alias exactly, after normalizing, and scores every spelling as the real words. Both live in the `voiceLaunchJSON` mirrored setting; a setting saved before `triggerAliases` existed decodes with none, and the field is left out of the JSON while empty. An alias may not equal another command's trigger or alias (`VoiceLaunchConfig.validate`), or another entry's name or alias in the same list (`addEntryAlias`, Teach). All the rules are in `VoiceLaunchAliases.swift`.
- **Near misses.** `plan(for:in:)` returns `PlanResult.nearMiss(VoiceNearMiss)` (pure, in `VoiceLaunchNearMiss.swift`) when nothing matched but the words were close. Entry near miss: a command's fixed words matched and a list slot found no entry; it names the command, slot and list, the words heard at the slot (one word, or also two when a text slot follows, or up to the next fixed word) and up to three entries ordered by simple edit distance on normalized text. The ordering only orders suggestions; nothing is saved without a click. Trigger near miss: no command matched at all; it carries the first one or two words. The Core attaches the near miss to `VoiceCommandDelivery` (`nearMiss`, optional on the wire; an older Mac ignores it and types the words with the old notice). On a current Mac, both entry and trigger near misses type nothing: the transcript goes on the clipboard and `VoiceNearMissNoticeController` shows an interactive notice on the target Mac ("Heard “norm” — who did you mean?"). Choosing a name calls `VoiceNearMissFix.fixEntry` (adds the alias with the same conflict rules, then plans the same transcript again and runs it, confirm steps included); a trigger near miss offers "Make “…” another way to say…" with a picker of commands (`fixTrigger`, no re-run). Both write through `AppSettings.updateVoiceLaunch`, so they reach every Mac by the settings mirror. "Try it" shows the same fixes (`VoiceNearMissFixView`). The re-run uses the words as spoken (no clean-up of the clean-up slot).
- **Teach.** Each list entry and each command trigger has a Teach button (`VoiceTeachSheet`). The person records four takes (the Record button; a take ends after two seconds of quiet or six seconds in all, `VoiceTeachEndpointer`; a "Stopping…" bar and the seconds left show while it records); audio is accumulated only then, through the Edge runtime's existing 16 kHz mono recorder (`VoiceTeachRecording`, `VoiceTeachSession`). Each take goes through `DictatorViewModel.transcribe(rawOnly: true)`: the same speech path as dictation (the Core's speech sources in order, the same Whisper hints as command mode) but with no clean-up, no dictionary replacements, no paste and no history; the audio is dropped. On a connected Mac the request is `EdgeMessage.transcribeRequest` (the header, then one binary frame) answered by `CoreMessage.transcribeResult`; both are new message types an older peer ignores, and `EdgeProtocol.version` stays 2. On the main Mac `CoreHost.transcribeForTeach` is the same function. `VoiceTeach` extracts the alias: with a real phrase ("WhatsApp Noam") and its fixed words heard, the alias is the words at the name's place; otherwise the whole transcript is shown for the person to tap the words that are the name; for a trigger the whole heard text is the candidate. New distinct candidates are pre-checked, ones equal to the name are hidden, and conflicts are shown in words and can't be saved.

Teach, Check name and Shortcuts Dictate reserve this Mac's microphone until their take ends or is cancelled. Another take or dictation cannot replace their buffers, and stale stop/cancel messages cannot end a different owner's recording. While reserved, the Mac reports its microphone unavailable for new broker sessions. A racing `capture.start` gets a session-scoped `capture.failed`; the main Mac accepts it only from that session's microphone owner and only before audio has been handed to transcription. This new message is ignored by older peers without changing the protocol version.

**Background Commands.** Optional `VoiceStep.background` runs a Terminal action on the Mac executing the plan, through the injected `runProcess`, without a Terminal window. It is an acting step requiring a command and cancel pause. The unchanged command allow-list is rechecked at run time; `/bin/zsh -f -c` receives folder and spoken text as positional arguments, with the existing leading-dash protection. The shell is noninteractive, stdin/stdout use `/dev/null`, and only basic user/locale values and a fixed search path enter its environment. Timeout, Esc and task cancellation kill its process group, including children. `timeoutSeconds` defaults to 60, with a range of 1...600. A plain failure alert shows exit status and a bounded stderr snippet, keeping words on the clipboard; diagnostics contain status and duration only. Older Macs ignore the flag and run visibly. No new step kind, store or protocol version is introduced.
**Commands limited to apps.** `VoiceCommand.onlyInApps` is a mirrored list of up to 20 bundle identifiers; empty means everywhere. `HotkeyService` samples the pressing Mac's frontmost app before showing UI and sends optional `appBundleId` on the existing `shortcut.mode` message. The broker retains each presser's sample through settling, uses the initiator's sample, then consumes it for matching. It never enters history or logs. Missing context from older Macs, Try it or Apple Shortcuts means unknown: only global commands qualify. Among equally matching phrases a scoped command beats a global command; equally fitting scoped commands still tie. Validation permits disjoint scopes and global fallbacks, but rejects overlapping scoped duplicates. Near-miss suggestions carry eligible command IDs rather than the app; choosing a missing name replays only that chosen command.
**Starting Commands without speech.** `VoiceCommandTriggerController.run` checks enabled state and required spoken parts, renders through `VoiceLaunchEngine` with empty slots and no transcript, then calls the local executor with `.keyboard` or `.otherApp`. Both main and connected Macs read `AppSettings.voiceLaunch`, already populated by `CoreSettingsMirror`; there is no second configuration. `WorkspaceHotkeyCoordinator` observes both mirrored settings and refreshes the existing Carbon registry. Commands and routines cannot share keys, and recording a key suspends both. Pause (`isPromptCapturePaused`) stops typed-history capture, not commands: keyboard starts run through it, as routines do, and only `dictator://` links wait for it to end. Links arrive through `AppDelegate.application(_:open:)`, and one that launches the app is held until startup finishes.

`dictator://run?command=<exact name or id>` requires per-command opt-in. Only the saved command reaches rendering; extra query parameters are ignored. Acting or Terminal steps require a fresh Allow/Cancel dialog with the saved name and actions. One start owns the dialog/execution lock, and links are limited to one attempt per two seconds. Malformed links are ignored without logging their contents. SwiftUI receives URLs; the controller refuses them before `applicationDidFinishLaunching` and in Debug or non-production bundle IDs. No stored keys, step kinds or protocol versions change.

**Command files.** `CommandFile` transforms the version-1 `.json` envelope (`dictatorCommands`, `commands`, `lists`) separately from stored settings. Export strips command IDs and launch permissions, includes list entries only by explicit choice, and blanks whole values containing paths or addresses unless included. Commands offers bounded import and a review sheet; unknown step kinds or higher formats fail before reaching settings. Imported commands get new IDs, stay off and lose keyboard/other-app permissions. Lists merge by normalized name without replacing overlapping entries. Confirmation validates the combined candidate against current settings and uses `updateVoiceLaunch`, including on a connected Mac. Existing validation requires missing values and phrase clashes to be resolved in review before saving; no command runs during import.
**Recent commands (per Mac).** `CommandActivity` records each `VoiceLaunchExecutor.run` outcome once, keeping 50 in `Application Support/Dictator/recent-commands.json` with background, atomic file writes. Only command identity/name, time, trigger, outcome and audited fixed failure titles are saved. Plans, spoken values, app/window names and arbitrary errors are excluded. History off or Pause suppresses new records. Home shows five; Clear removes the file, as does uninstall's optional data removal. No in-app delete-all-history action exists. The log is outside replication, settings, SwiftData and Datasets. Run Again retains the resolved plan only in memory, reuses its pauses on this Mac (including connected Macs), and clears on Pause. Welcome optionally adds safe catalog starters through `updateVoiceLaunch` only with no existing commands, reuses Try it matching and observes success even with history off.

## Typed history

Optional and off for new users. When on, Dictator saves what you type in chosen places, next to your dictation.

- **The decision** is made in one place, `AppSettings.captureDecision(for:modality:)`, against `SurfacePolicy` v2 (per tool: typed and voice switches, plus rules for exceptions and `scrub_secrets`). `HistoryRepository.record` checks it again and stores why the row was saved. The policy lives in the app and is mirrored between Macs.
- **Tools, host apps and connectors** come from `shared/tool-catalog.json`; user additions go in `~/Library/Application Support/Dictator/custom-tools.json`. Successful custom-tool writes publish an observable catalog snapshot. Removing a chosen custom tool also removes only its per-tool surface-policy entry through the existing shared-settings mirror; other Macs’ unknown tool IDs and explicit exception rules are retained. Write errors keep the previous catalog and policy visible. Existing history is unchanged.
- **Capture** (`Services/Capture/`):
  - `TypedPromptCapture` reads the keyboard and decides at submit, using `SurfaceResolver` (process table, tmux, ssh, editor focus, browser URL). It holds no keystrokes at all while no typed place is on. A focused password box or secure input discards the draft. A browser has one draft per process, across every field and tab, so there only the text box read at submit counts as a prompt, unless the user chose to save everything.
  - Coding tools can instead be captured exactly by a hook in the tool's own settings (`shared/connectors/dictator-capture`, a POSIX shell shim) or by reading the tool's transcript files.
  - Permission to save is mirrored; capture methods, hooks and the shim belong to each Mac. `PromptCaptureCenter` checks local signatures and setup at launch, after local or mirrored policy/method changes, and every 300 seconds. An enabled, locally installed tool needs setup when its chosen (or recommended) hook or shim is missing; tools that are off or absent do not raise a banner. A chosen history-file or keyboard method is preserved. An unchosen non-hook connector still needs the initial method setup.
  - Home, Datasets and Typed History show the same plain setup banner naming the affected tools and this Mac. **Set up** is the explicit local action that runs existing connector setup, keeps configuration backups and retains a result for every attempted tool, so later successes cannot hide failures. At launch, an existing shim is updated when a tool uses the hook method; matching shim versions are left untouched. Status checks never write tool configuration or recreate a deleted shim. Removing a hook or shim stops that connector until the user sets it up again; external repairs are reflected without relaunching. Typed history remains off until the user opts in.
  - Servers reached over SSH get the same hook, installed and collected over the user's own SSH (`RemoteCaptureService`). Nothing listens on the server.
  - `PromptRecorder` removes duplicates across sources and, when `scrub_secrets` is enabled, replaces recognized secret formats with `[redacted]`. Arbitrary passwords in ordinary prose are not reliably detected.

## Datasets

Datasets prepares saved prompt history for whatever analysis tools the user chooses. Dictator performs no analysis, inference, advice or automatic agent runs.

- **Screen.** The sidebar calls it *Datasets*. Its *New* tab puts the common choices first (time range, Sent to, input, text). Everything else is folded behind a one-line summary of its current state: more filters, cleaning and privacy, format and details, and the raw file. The preview shows prepared prompts and “Matched X, took Y” counts before and after the limit. **Create dataset** saves a snapshot. The bar then offers **Copy prompts**, **Save as one file…**, **Copy location for a local agent** and a menu with Copy path, Show in Finder, save a copy elsewhere, attach a report, run a local tool and delete. The ready state lasts until the user changes a choice (`DatasetStore.editRevision`); new history arriving does not clear it. The *Saved* tab lists snapshots with the same actions. Datasets uses plain language in both voice modes.
- **Chat handoff.** `DatasetHandoff.render` is a pure renderer of the saved prepared records and manifest. `DatasetStore.prepareHandoff` loads the integrity-checked canonical `records.json` and renders off the main actor, without rereading history. **Copy prompts** copies the complete self-contained text; **Save as one file…** uses `NSSavePanel` with the dataset name and `.md` extension and writes exactly the same UTF-8 text for upload to a chat app. The text retains the existing brief's opening, date range, data-not-instructions warning and applicable redaction note, then compact JSON Lines in chronological order with date (ISO 8601), input, optional destination, optional project basename and prepared text, ending in `Task:`. JSON encoding escapes prompt newlines; nil fields are omitted. With context excluded, only date, input and text remain. It has no folder path or file list. Size is shown as a prompt count and approximate tokens (character count divided by four, rounded up), with no agent/model recommendation. Above the named 200,000-character paste threshold, saving a file becomes primary and a line explains that it is too long to paste reliably; copying stays secondary. The separate `DatasetPackage.agentBrief` retains the folder/file brief as **Copy location for a local agent**. Neither handoff runs anything or chooses a provider.
- **Where prompts went.** `DatasetDestinationResolver` gives each row one destination from what it recorded, using the tool catalog. In order: the recorded tool; the tool that owns the app (`com.openai.codex` is ChatGPT, the merged app), except editors, which host many things; the tool that owns the website. Failing that: *Terminal or agent app, tool not recorded* for terminals, `terminal://` destinations, multiplexers (Herdr, tmux, zellij) and agent apps that run several tools without recording which (T3 Code), or the app under its catalog or readable name. *Sent to* groups these by vendor (all Anthropic, then Claude and Claude Code), then terminals, other apps and not recorded, with counts. *Saved by* (dictation, typed history, connected AI tool, imported) replaces the separate capture-method and origin filters. Filters with one value in history (project, computer, remote host, session) are hidden unless set.
- **What’s being saved.** Datasets has a collapsed “What’s being saved” disclosure inside its card. It lists switched-on tools installed on this Mac or with saved dates, with their selected or recommended capture method and observed state on this Mac; other switched-on tools are summarized in one count. Latest prompt dates are grouped by tool and recorded originating computer from the full `DatasetStore.rows`, independent of dataset filters, including replicated and imported rows already in history. Existing Datasets app/website attribution is used when a row has no explicit tool; an unidentified terminal never implies a tool. Missing computer IDs remain “Computer not recorded”; no dates are invented for an empty history. The section contains no prompt text, recency thresholds or assessment, and reads no tool logs or other Mac’s store.
- **Read locally.** `DatasetStore` reads plain `DatasetRow` values from this Mac's history through `HistoryDatasetStore`. It loads only when opened and refreshes after local history changes. Replicated rows are included when present; no other Mac's store or tool transcript logs are read for this screen. Typed history remains optional and off by default.
- **One selection.** `DatasetQuery` ANDs inclusive date/time bounds, input, saved-by, captured/imported status, website, remote host, full project directory, originating computer, exact session ID, stored word count and a text condition (contains, all/any whitespace-separated terms, or case-insensitive regular expression). **Sent to** accepts several destinations or `vendor:` keys with any-of semantics. The optional `destinations` list replaces the legacy single `destination` when present; old saved queries still decode. Advanced filters include **Not sent to**, using the same destination choices (any match rejects a row), and **Leave out text**, which rejects any whitespace-separated term as a case-insensitive substring. Exclusions win over inclusions. All text conditions inspect stored text before preparation. **Take** defaults to All, or limits to Newest N, Oldest N or Random N after every filter and before cleaning. N must be positive. Random sorts ascending on SHA-256 of UTF-8 seed + newline + lowercased row UUID, with UUID tie-breaking; the query stores the seed and **Shuffle** replaces it. A missing seed uses `0`. Every result is chronological with UUID tie-breaking, including random samples. Preview and saved datasets use the same selection. New stored query fields are optional, and reset/saved selections include them. Invalid filters clear the preview and disable creation. There are no inferred sessions or implicit date ranges.
- **Prepare a copy.** `Dataset` normalizes line endings and optionally trims surrounding whitespace, removes empty prompts, removes exact repeats within the same recorded place/project/session/computer/remote host/input, hides recognized credential patterns using `SecretScrubber`, and excludes context or timing metadata. Missing session IDs leave deduplication bounded by the other recorded fields; duplicates keep the earliest entry. Redaction happens after deduplication and applies to text, included metadata, the package name and the manifest query, including excluded text and destination lists. It does not anonymize ordinary prose or reliably hide arbitrary passwords. History itself is never modified. Exported word counts are recomputed from prepared text; the original stored count, original modality, source, capture context and inference duration are also available when applicable.
- **Package.** JSONL, JSON and CSV share the exact prepared records shown in the preview. Every package also includes canonical `records.json`, `manifest.json` and `SCHEMA.md`. The versioned manifest records the selection, preparation choices, matched/taken/exported/removed/redacted counts (matched before the limit, optional `takenRecords` after it and before cleaning, exported after cleaning), date range, stable record IDs in the data and SHA-256 hashes for the data file and canonical JSON. Readable dates are ISO 8601 UTC at second precision; numeric Unix-second fields preserve subsecond record timestamps and filter bounds. Local saved selections preserve exact filter bounds. Absent JSON fields and blank CSV fields mean unknown or excluded. CSV quotes multiline values and prefixes formula-leading values with an apostrophe; JSON preserves the text literally. Filter values can be omitted from the manifest independently of per-record metadata. A query containing a redacted credential is descriptive and cannot necessarily be rerun verbatim.
- **Local archive.** Saving or exporting creates an atomic snapshot under `~/Library/Application Support/Dictator/Usage/<UUID>/`; later history changes do not alter that snapshot. Export copies the package to a user-chosen folder and never overwrites an existing package. Reports selected by the user are copied into that package's `Reports/` folder without interpretation. A package is independent of history retention/deletion; delete it separately from Datasets › Saved when no longer wanted. Saved selections, CLI setup, known computer names and archive paths belong to this Mac (`Usage/preferences.json`), not the shared settings mirror.
- **Optional CLI delivery.** From an archived package, the user chooses an absolute local executable, literal arguments (one per line), and optional instructions. An explicit Run action starts it using Foundation `Process`, with the package as working directory. Standard input is a JSON envelope with `instructions`, `manifest`, and the canonical prepared `records`, regardless of export format. No shell interpolation, provider/model selection, authentication, installations, remote execution or automatic reruns are performed. Existing user credentials and environment are inherited; the executable's directory and standard local CLI locations are added to PATH. The user-selected CLI controls what happens to the data. Input, invocation, exit code and complete stdout/stderr are stored under `Reports/CLI-<UUID>/`, including nonzero exits and cancellation after startup. File-backed I/O writes output into the archive while the CLI runs and avoids pipe deadlocks; app teardown cancels the directly launched process. Before sending or exporting, both data hashes are verified. Cancellation terminates the directly launched process; a CLI that launches its own descendants is responsible for them.
- **Import.** `Services/Import/` reads ChatGPT and Claude exports, Claude Code and Codex logs, Gemini Takeout, Wispr Flow (read-only), text and JSONL. The existing preview/deduplication/tombstone-aware import and batch removal are retained in Datasets. Imported history is added only after explicit confirmation.

## Workspaces

`WorkspaceLaunchConfig` holds versioned, ordered routines. `AppSettings.workspaceLaunchJSON` goes through `CoreSettingsDTO`/`CoreSettingsPatch`, `RepoServer` validation, `LocalCoreSettingsRepository` and `CoreSettingsMirror`. The wire field stays `workspaceResetJSON` and is optional; older peers ignore it. Deleting all routines sends an encoded empty config rather than a missing field. Wire validation stays strict. Local editing preserves older routines with unsupported shortcuts, clears those shortcuts and disables their routines until reviewed; malformed saved JSON is preserved until the user explicitly clears it. Live window snapshots and recovery never travel between Macs (remembered layouts, below, do). An explicitly empty main-Mac setting adopts local routines once; otherwise the main Mac supplies the whole definition list. Offline edits use the existing settings mirror and do not merge individual routines.

Local routine saves and deletes use `AppSettings.updateWorkspaceLaunch`: after validation, it updates linked voice command display names only when they still equal the old routine name, without changing the phrase. Deleting removes all actions linked to that routine and drops only commands left empty; other actions and custom names survive. Deletion names the affected phrases in its confirmation. Explicitly clearing all routines also removes their links. These voice changes use `updateVoiceLaunch`, so connected-Mac edits travel by the same mirror. Applying an incoming settings snapshot does not run these local edit hooks again. An off routine retains its links and voice execution reports the existing routine-is-off failure.

`WorkspacePlanner` turns synthetic or live snapshots into deterministic move/hide operations. `NativeWorkspaceLaunchAdapter` calls Accessibility and AppKit APIs, with the optional raw application attribute described below; `WorkspaceHotkeyRegistry` uses Carbon to register only chosen combinations. No Hammerspoon, third-party window manager, private Spaces API or model is needed. The interface lets users choose running apps and, for placements, installed apps, an app bundle through an open panel, or a typed bundle ID and app name for another Mac; no app identifiers are built into code.

Tracking starts only while a routine is enabled. Activation, deactivation, launch and termination notifications maintain in-memory activity timestamps, starting with the apps present when tracking begins. It reads no window titles, contents or keystrokes and does not poll. The last-used app and Dictator are protected from hiding; hiding does not save or close apps. Unknown activity is left alone.

Preview captures geometry without moving windows. Run captures again, bounds Accessibility messaging and executes the chain with a five-second budget between operations. Accessibility reads and geometry writes run on a dedicated serial queue off the main actor; the chain yields between operations. The adapter writes position before the first full-height resize, reads back each stage, reapplies position and checks the resulting frame. If the old size constrains the initial move, a bounded wait can continue to resize and final positioning. One corrective pass separates position and size changes with readback. Each stage has at most six observations and a soft retry deadline; IPC, a final operation, mode restoration and rollback can take longer than the chain budget. Standard, movable/resizable windows are eligible; hidden, dialog and full-screen windows are skipped. Minimized windows are candidates only for Remember and Place apps preparation, described below. Position must be within four points; character-cell size reductions of at most 40 points are accepted. A persistent mismatch stops execution and retains recovery. Applications can constrain geometry, but a mismatch alone does not establish its cause or a minimum size.

**Scoped accessibility mode.** Before a native move or restore, the adapter reads the target application's optional `AXEnhancedUserInterface` attribute and whether it reports being settable. If its original value is true and settable is true, and neither macOS VoiceOver nor Switch Control is enabled, the adapter attempts to disable the mode for the operation. Other accessibility clients are not detected and may depend on that mode; the temporary change is not guaranteed transparent to them. An unknown original value, false value, unavailable settable result or either enabled built-in assistive feature leaves the mode untouched. This is application state, not a macOS permission grant or global preference change.

Every attempted disable creates a restoration obligation, even when its acknowledgement reports an error or the first read still says true. A failed acknowledgement can coexist with a changed observed value. If the post-disable state cannot be read, geometry is skipped and restoration is still attempted. Restoration writes the original true value, then requires two true observations separated by a delay; it makes at most three attempts. Unknown or false restoration leaves an explicit error and an in-memory intent keyed by process ID, launch date and bundle ID. The adapter retries after bounded delays and before subsequent capture/move requests, including Undo, and blocks new operations while restoration remains unresolved. Stale process identities are discarded. This intent does not survive Dictator exiting; an unresponsive app, revoked Accessibility access or process termination can prevent immediate confirmation. It is separate from the window-frame Undo snapshot.

The raw `AXEnhancedUserInterface` name is not declared in the inspected public AX attribute constants or AppKit accessibility headers. It is an optional compatibility workaround whose support must be checked and whose effects must be observed, not a documented cross-process tiling primitive. The documented geometry path remains individual position and size attributes through `AXUIElementSetAttributeValue`; no atomic frame setter was found in the inspected public AX interface. The scoped workaround follows the kind of animated-frame interference described in [Rectangle's implementation notes](https://github.com/rxhanson/Rectangle/blob/main/TerminalCommands.md#control-enhanced-ui-handling); that does not establish who enabled the mode or a universal macOS/application defect.

The adapter validates retained window/process identities and attempts to reverse partial geometry changes. The executor retains original frames once per window, plus apps hidden by that run. Restore clamps saved frames to their original display at its current position and resolution, or falls back to the main screen if that display is disconnected. Expired window/process identities are dropped with an explanation; temporary failures remain available for retry. Restore retries remaining failures and never unhides an app that was already hidden before the reset. Frame recovery is memory-only and available until the app exits or a later reset replaces it; it cannot recover document contents.

**Remembered layouts.** "Remember" records up to 40 eligible open windows on the current desktop, excluding minimized and full-screen windows (`WorkspaceSavedLayout`: each window's app, screen, place as fractions of that screen, rounded, and optional stack position with zero frontmost; never titles or contents) and saves it as a step keyed by `WorkspaceMacIdentity`, so one routine can hold a layout per Mac. The step is `arrangeWindows` with the optional `remembered` field and its apps in `bundleIDs`, so a build without the field still reads the routine (and tiles those apps). `WorkspaceLayoutRestorer` maps remembered screens to current ones (same id, same name, built-in, main; otherwise the main screen with a note) and matches each app's open windows to its remembered ones by size and place; unavailable apps/windows are reported by their actual state and extra windows are left alone. These positions and app names travel inside the shared routine; run replies carry only summary counts and plain notes.

Remember captures front-to-back order through the public on-screen CG window list, matching layer-zero windows by process ID and rounded bounds. Equal bounds in an app consume matches in Accessibility window order, focused first. Unmatched windows have no stack position; older layouts decode and stack nothing. The saved drawing paints back to front. Matching includes windows whose geometry is already correct in the stack plan.

Remember and Place apps apply their final, post-opening/post-unminimizing stack plan through the adapter. It lifts only windows covered by overlapping layer-zero windows that are not wanted higher, ignoring Dictator and wanted windows absent from the current desktop. Up to three passes within the run deadline re-read live order to correct activation overshoot. Each lift sets the application's public Accessibility frontmost attribute (unless already true), polls readback for at most about 0.4 seconds, then performs the window raise action. It does not use `NSRunningApplication.activate` or private window APIs. Lift refusals add one app note per Mac without stopping the routine. Focus returns through Accessibility unless an on-screen window of the previous app overlaps a lifted window; Dictator always gets focus back. A run with a stack plan logs one `workspace: stack` line with pass and lifted counts, final wanted bundle-ID order front to back, and whether focus returned.

**App placements.** A `WorkspaceAction` can carry optional `placements` and `openMissingApps`. Its kind stays `arrangeWindows` and `bundleIDs` names the apps, so older builds ignore the fields and tile those apps as before. Absent `openMissingApps` means off for both Remember and Place apps; new steps of either kind set it on. Remember again and forgetting one Mac preserve the existing optional choice. Each placement stores an app's bundle ID/name, Mac identity/name, generic `WorkspaceDisplayChoice` or specific stable display UUID/name, and a separate string-backed `WorkspacePosition` (full, halves, quarters or thirds). Existing enum cases and protocol version stay unchanged. Validation bounds placements to 100 per step and 20 Macs, bounds strings, rejects duplicate app/Mac pairs and preserves the 128 KB config limit.

A Mac plans only its own placements; unplaced apps remain untouched. A setup-derived `WorkspaceMacIdentity` alias lets the editor assign offline Macs before they can return their hardware identity in a capture. Each Mac recognizes its own alias alongside its hardware key; execution never matches by display name or Mac name. Each app's eligible windows share its tile, and are raised back to front with its focused window on top. Specific monitors match by stable display UUID; a missing monitor falls back to that Mac's main screen with a note naming both. Generic choices reuse `WorkspaceDisplayResolver`. Before planning, the adapter checks installation/running state, opens missing local apps for Remember and Place apps when requested and waits for their first standard window. Remember uses only the apps in this Mac's saved layout, never the routine's combined `bundleIDs`. Opening and waiting share at most eight seconds per app and fifty seconds overall, reserving ten seconds of `VoiceLaunchReadiness.workspaceRunBudget` for capture and movement. Accessibility IPC has bounded messaging timeouts; these deadlines are soft around an in-flight system call. Missing apps/windows are notes and don't block other placements. Undo restores pre-move geometry and never quits opened apps; its status adds that sentence only for runs that opened apps.

Remember and Place apps capture minimized standard windows as candidates through `WorkspaceLaunchAdapter`. Remember counts eligible visible windows first and unminimizes only the deficit up to the saved count per app; Place apps unminimizes one only if that app has no eligible visible windows. Multiple steps reuse candidates up to their largest required count. Preparation has a five-second soft deadline between window operations, shortened when necessary to leave two seconds for recapture and five for movement within the existing run budget, with bounded AX setters and readback; a refusal is a note and other apps continue. After any unminimize attempt the controller recaptures and replans, never moving stale preview or preparation handles. Original frames and minimized flags enter the existing per-Mac recovery before recapture, so Undo can re-minimize those windows even if recapture or a later move fails. Side by side and grid do not bring windows back.

Preview opens and unminimizes nothing. It uses the same candidate selection to draw minimized windows in their planned places with “will come back” notes. It uses the same planner, draws local placements (closed apps marked “will open”) and adds one line per other Mac. The editor keeps remote monitor discovery only in temporary view state: it reuses fleet capture replies, which now include displays even when no eligible windows exist. Remember still excludes empty layouts. Offline Macs offer generic choices plus the placement's stored monitor. Remembered layouts retain numeric AppKit/CoreGraphics display IDs, with their existing name/built-in/main fallbacks. `WorkspaceDisplay.stableUUID` is optional for older snapshots; placements store and resolve that UUID, without matching monitor names. Capture and monitor discovery refuse while a run, preview, Undo or another capture owns the controller’s busy lock, before touching handles. Busy fleet replies are carried in an optional `busy` list and Remember names those Macs separately from unanswered ones. Unavailable editor discovery keeps saved choices and retries on the next opening. The Place apps picker shows running apps and its stored choice immediately; a `.task` adds installed apps using Commands’s shared background enumeration. Nothing beyond the placement is cached in shared settings.

**Tab sets.** A `WorkspaceAction` can carry optional `tabSets`, each one browser window: a Mac, a browser, an optional profile and addresses in tab order. Its kind stays `arrangeWindows` and `bundleIDs` names the browsers, so older builds ignore the field and tile those browsers. `WorkspacePlanner` gives a tab step no operations, and `localApps` returns nothing for it, so window capture, opening of missing apps and skip counts ignore it. A Mac opens only its own sets, in routine order. Tab steps before the routine's last window step open after missing apps and before windows are captured, so later steps can act on them. Tab steps after it open once the windows have moved, so a Place Chrome step doesn't move the new windows, and they don't open if the window work stopped. A tab step between two window steps opens first, which is the one exception to the editor's "Steps run in order". A cold browser gets up to eight seconds for its first window.

Addresses are limited to `http` and `https` (`WorkspaceTabAddress`), when saved and again at run time, and go after `--`, because a flag in the address list otherwise takes effect. Chromium browsers silently create a profile that doesn't exist, so `WorkspaceTabWords.blocked` and `WorkspaceBrowsers.launchRequest` both confirm it first, from `Local State` and from the profile's folder. `WorkspaceBrowsers.installed` lists every app that opens `https`, so any browser appears. The `browsers` key in `shared/tool-catalog.json` names the ones whose profiles Dictator can read, using only the profile folder, `name` and `profiles_order`, never sign-in details. Those browsers open through `openApplication` with `createsNewApplicationInstance` and `--new-window`, which Chromium hands to its running process. Any other browser gets its addresses through `NSWorkspace.open(_:withApplicationAt:configuration:)` and decides for itself where they go, so no shared wording promises a new window and the editor says so for that browser (`WorkspaceBrowsers.opensItsOwnWindow`). Nothing activates a browser.

Without Accessibility, or in a browser that doesn't make its own window, each run opens the pages again. Tabs can't be undone: "Tabs opened by this run stay open" joins the Undo line, a run of a routine with no window steps offers no Undo of its own, and it leaves an earlier run's Undo in place, including its link to other Macs. A Mac with no window work of its own in a routine (`onlyOpensTabs(macID:aliases:)`) needs no Accessibility and reads no windows, so a Mac without that permission, such as a server, can still open tabs. A browser that doesn't answer in time throws `WorkspaceTabOpenTimedOut`: the request can't be taken back, so the note says its tabs may still appear, and they don't count as opened. If a Mac had sets and opened none, the run reports a failure, so voice stops and the other Mac hears about it; a partial result is a note. A failure line names browsers but never a profile, because a voice alert is logged word for word. Notes in the app can name the profile, and `workspace:` logs carry `tabs=N` only. The editor gets each Mac's browsers through the existing capture: `answerCaptureRequest` adds optional `WorkspaceSavedLayout.browsers`, stripped before anything is saved. When capture fails, for example without Accessibility, it still sends the browsers in a layout with no windows and an optional `captureError`, which Remember reports as before. A Mac on an older build sends none, and its stored choice stays selected. An older build that saves routines drops `tabSets`, as it drops any field it doesn't know, so every Mac needs this build before anyone relies on tab steps.

**Window groups.** `WorkspaceRoutine.showOnly` makes a routine a group, the baseline for switching work without changing desktop. Optional `keepVisible` lists apps that stay showing. Both are optional, so an older build reads the routine and hides nothing. `groupApps` is the routine's window apps, its tab browsers and `keepVisible`, on this Mac. A routine hides nothing on a Mac where it has no work of its own, so fan-out can't empty another Mac's screen.

A group run shows its apps first, keeping the process it showed so Undo never hides a restarted app, because a hidden app's windows may not be readable, then opens apps and tabs, captures and moves windows. `WorkspacePlanner.focusPlan` then brings a group app forward, since macOS won't hide the front app, and hides the rest with `hideOtherApp`. One app refusing is a note, not a stopped routine. If no group app is running, nothing hides, so the screen is never left empty. Hiding is the normal macOS hide: hidden apps stay in Command-Tab and the Dock. On macOS 27, `hide()` and `unhide()` return false even when they work, and the app changes 13 to 30 ms later, so the adapter waits up to half a second for the state itself and ignores the return value. Minimising took 2.3 s or more for eight windows, so it isn't used.

`WorkspaceTabWindowTracker` knows the browser windows Dictator opened: the set, the window handle, and the set's `signature`. Handles die with the browser or with Dictator, so tracking is in memory, on each Mac. Polling capture after a launch finds the new window, only for a browser that makes its own window or a set with a place. A window is tracked only if exactly one new window of that browser has appeared and is still alone 150 ms later, because a person can open one at the same moment. With two, Dictator tracks and places neither. A later run reuses a tracked window instead of launching, which is why tabs no longer add up. Editing a set's browser, profile or addresses makes it a new window, because bringing back the old one would show old pages. Tracked windows of other routines are removed from what the planner sees, so a Place Chrome step can't move another group's window.

When a group keeps an app showing that has tracked windows of another group, those windows are parked with `WorkspaceParking`, at the far corner of all screens. macOS won't let a window fully leave: it stops 31 to 40 points short of the corner, leaving a sliver about 1 point wide. So `parkWindow` sets only the position, in about 40 ms, reports where the window landed, and the caller checks that it's out of reach. If it isn't, the window goes back. `moveWindow` can't do this job, because it insists on an exact landing and rolls back otherwise. `WorkspaceTabWindow.parked` holds the state, because position can't: showing a hidden app makes macOS push its parked window back on screen, so a window can be parked and in view. Its `home` survives that. Only tracked windows are ever parked; a person's own windows never are, and a person's off-screen window can still be placed. A window is parked only if its group has another usable window of that app, and a group with no usable window hides nothing, so a run can't leave nothing showing. `WorkspaceParkedStore` writes `workspace-parked.json` before each park, with only each app, home frame, parked spot and time, and if that save fails nothing is parked, so a crash can't strand a window. A window comes back through Undo, the "Bring back" row on the Workspaces page, quit (bounded to two seconds by `QuitGuard`), or the next launch. Launch rescue moves a window only if it's out of reach and within 64 points of a recorded or current parked spot, and at most one window per record, so a person's off-screen window is left alone. A record with no matching window stays for 24 hours, because a browser may restore its windows late.

**Across Macs.** "Remember on all my Macs" sends `workspace.remember.all` to the main Mac, which asks every connected Mac (itself included) with `workspace.capture` and answers with each Mac's layout and the names of those that didn't answer within 8 seconds. Running a routine that has layouts or placements for other Macs also sends `workspace.run.all`: the main Mac asks every other Mac to run it on its own windows (`workspace.run`) and reports back one line per Mac; a Mac with neither a remembered layout nor placements for it stays silent. Named Macs missing from replies are reported with their unplaced apps, including when no fleet connection exists; voice execution surfaces that as a failure after local work finishes. Fleet run replies have the same 60-second workspace budget. Undo after such a run reaches the same Macs. All of these are new message types, so older peers ignore them. The main Mac only relays: each Mac captures, plans and moves its own windows, and the routine is saved by the Mac that asked, through the usual settings mirror.

Skip notes are scoped to this Mac's selected apps, combined once per app/reason census, and emitted once by the planner. The result has one outcome line followed by app notes per Mac; the controller does not append the capture skips a second time. An app with windows on another desktop is never called closed, and partial moves identify only the windows left there. Slow/unreadable captures make no other-desktop inference. macOS has no public API for moving windows between desktops: Dictator uses no private CGS/SkyLight calls and never switches desktops.

Every run and Undo uses `HotkeyService.recordDiagnostics` with `workspace:` start/end lines in `~/Library/Logs/Dictator/hotkey.log` on its own Mac. Lines include the Mac identity/name, routine ID, short operation ID shared with fleet Undo, local/remote origin and click/keyboard/voice/remote trigger, duration, unique windows moved, windows brought back or re-minimized, apps opened, skip counts by reason and bundle ID, and plain failures. The starting Mac logs one reachability/count line per other Mac, including unanswered requests. Optional `WorkspaceRunCounts` travels in `workspace.run.result` and `WorkspaceRunReport`; older replies remain readable and are logged with counts unavailable. Logs never contain window titles or typed text.

Browser tab grouping/archiving, save-and-quit and desktop/Spaces management are not implemented. Legacy tiling steps do not reopen apps.

## First use and saved recordings

The welcome screen offers local speech setup through the existing Add an AI model flow, with a memory-based recommendation and explicit download action. Typed history is an unchecked optional next step. Readiness requires this Mac’s recording permissions and either an installed model on an online Mac or a reachable speech server from the configured source list; a configured address alone is not evidence of readiness.

Home shows the count of recoverable recordings, a retry action for the newest, and a link to review all of them in History & Privacy. Each recording shows its removal date from the same 14-day retention constant used by startup pruning. The 512 MiB aggregate limit can remove older recordings sooner. Recovery keeps using the existing local store, history save and clipboard path; it never pastes into the formerly focused app.

## Startup and recovery

Settings › General configures this Mac’s login registration through SMAppService.mainApp and whether opening Dictator shows its window or leaves it in the menu bar. Registration status is read from macOS, including approval needed and unavailable states; errors never optimistically enable the switch. Turning it off leaves the current app running but requires opening it manually after the next login. Startup starts only after that user logs in; it cannot wake, unlock or boot another Mac. No setting silently registers another Mac.

Your Macs › After login lists each Mac’s actual startup report and explains how to configure it on that Mac. StartupReport is optional in EdgeCapabilities and SetupSnapshot.Machine, preserving compatibility with older peers. The normal capability refresh propagates changes. Offline reports are never presented as current. Startup settings remain per install and are deliberately outside CoreSettingsMirror; they are OS permissions, not shared dictation policy. Connections already wait/retry for network availability and main Mac recovery, and local fallback preserves recordings while shared history waits for reconnect.

An explicit --enable-login launch argument enables this installed app’s own registration for setup tooling; ordinary launches never change the user’s choice. It respects macOS approval and logs the resulting status. Hosted tests bypass startup initialization and use injected login operations, never real registration.

A saved recording holds every input channel summed, because the microphone's channel isn't known until the take ends. A retry levels it as live dictation is levelled (`AudioCaptureService.levelled`) before any speech source hears it.

A retry on a connected Mac uses its speech sources in their configured order, then its main Mac if those fail, so it needs no speech server key while connected. `RecoverySpeechPlan.steps` adds that last step whatever the sources are.

Quitting waits for a dictation to finish, for up to three minutes (`QuitGuard`). A main Mac's broker holds every Mac's session, so this covers a dictation on another Mac. It doesn't wait for a logout or shutdown. The installers quit Dictator with SIGTERM, which reaches the same check without Automation permission, and force it only after that wait.

## Updates

`Services/UpdateService.swift` wraps Sparkle’s `SPUStandardUpdaterController`. App startup initializes it only after the hosted-test and development-runtime guards. An empty or unexpanded `SUPublicEDKey` creates no updater, sends no update request and hides both the menu item and General toggle. Configured releases read the GitHub `appcast.xml` release asset and verify update archives with that public key. System profiling is disabled. Automatic checking defaults to on; Sparkle stores the choice in this Mac’s defaults, outside `CoreSettingsMirror`.

## App appearance

`DictatorDesignSystem.swift` holds the colour tokens, spacing and radius scales and text roles. `Views/DSComponents.swift` holds the shared frames: pages, tabs, buttons, sheets, empty states, step badges and floating panels. `MainWindowView` sets `.dsSecondary` as the default button style, and `DSSheet` does the same, so a bare `Button` is correct. Anton is for page titles and the brand lockup, and SF is for everything you work with. Settings is a page of the main window with tabs, and ⌘, opens it there. `scripts/tests/test_design_tokens.py` fails on raw fonts, sizes, radii and colours in views. The main window follows the Mac's appearance. `Views/BrandViews.swift` supplies the Home header, welcome artwork and process-local Anton/Jost registration. ## Removal on one Mac

`uninstall.sh` reads `hook_config` from the installed bundle's tool catalog before deleting the app. It removes only command/bash handlers containing `dictator-capture`, keeping other settings and hooks with a unique `.dictator-uninstall-backup` beside each changed file. OpenCode's dedicated plugin must match the bundled template; an edited plugin or malformed JSON is left for manual inspection. Copilot's hook JSON is filtered like other hook lists. Codex's shared `[features] hooks` switch is left alone because other hooks may need it. The local `~/.dictator` shim and spool are always removed, even if config cleanup fails.

Data deletion is a separate, default-no choice: it removes the complete `~/Library/Application Support/Dictator` tree (including `Usage` datasets, speech-server `Takes`, `Recovery`, `StoreRecovery`, speech models, the default server-owned `speech-server.token` and pasted `speech-server-remote.token`), app preferences and `~/Library/Logs/Dictator`. An overridden token or archive path is outside that tree and must be handled separately. Removing the optional speech server is another default-no choice, offered only when its LaunchAgent plist exists; it uses `launchctl bootout` and removes the plist, keeping external model caches. `--yes` and noninteractive input keep both data and the server. Open-at-login uses `SMAppService.mainApp`; the script directs users to disable it in the app or review Login Items. Remote SSH hooks, exported dataset copies and macOS permissions require separate removal.
